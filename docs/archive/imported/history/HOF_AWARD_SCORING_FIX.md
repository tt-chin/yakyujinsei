# 殿堂評価・個人タイトル得点漏れ修正指示書

## 1. 対象

- 開発リポジトリ: `tt-chin/yakyujinsei`（Private）
- 対象ブランチ: `main`
- 主な対象ファイル:
  - `docs/src/engine/game.js`
  - `docs/src/config.js`
- 公開用リポジトリ `tt-chin/yakyujinsei-site` は直接編集しないこと。
- `yakyujinsei/main` の `docs/**` を更新・pushした後、既存の GitHub Actions で公開用リポジトリへ同期すること。

## 2. 目的

殿堂評価の `honorScore(bucket)` で、一部の個人タイトルが得点に加算されない不具合を修正する。

国際大会の実績を殿堂評価へ加算する範囲は現行仕様のままとし、今回変更しないこと。

あわせて、シーズン終了時とオフシーズン確定後の年俸表示を自然な日本語へ修正し、アプリのバージョンを `1.0.1` へ更新する。

## 3. 現在確認できている不具合

### 3.1 野手タイトルの得点漏れ

現在は次の判定で部門タイトルを認識している。

```javascript
else if(h.includes('王')){sc+=160;king++;}
```

そのため、名称に「王」を含まない次のタイトルが殿堂評価へ加算されない。

- `首位打者`
- `最高出塁率`

以下は「王」を含むため、現状でも偶然加算されている。

- `本塁打王`
- `盗塁王`
- `打点王`

### 3.2 投手タイトルの得点漏れ

次の投手部門タイトルも「王」を含まないため、現在はすべて殿堂評価へ加算されない。

- `最多セーブ`
- `最優秀中継ぎ`
- `最多奪三振`

将来または既存データとの互換性を考慮し、次の一般的な投手タイトルも明示的な部門タイトル一覧に含めること。

- `最多勝`
- `最優秀防御率`

### 3.3 全リーグ共通の不具合

`honorScore(bucket)` は次の全リーグで共用されているため、上記の得点漏れは KBO だけではなく全リーグで発生する。

- CPBL
- KBO
- NPB
- MLB

### 3.4 「最優秀投手賞」の他リーグへの重複加算

投手の最上位賞は現在、受賞時にリーグ名を付けずに保存されている。

```javascript
const aw='最優秀投手賞';
h.push(`${y} ${aw}`);
```

さらに `honorScore(bucket)` ではリーグ一致判定より前に `最優秀投手賞` を加算している。

```javascript
if(h.includes(ace)){sc+=460;aceN++;return;}
if(!h.includes(lg))return;
```

このため、複数リーグでプレーした投手の場合、あるリーグで獲得した `最優秀投手賞` が、在籍した別リーグの殿堂評価にも加算される可能性がある。

## 4. 修正要件

### 4.1 部門タイトルを明示的に判定する

`h.includes('王')` に依存せず、得点対象となる部門タイトルを明示的に定義すること。

最低限、現在ゲーム内で生成される次のタイトルを対象とする。

#### 野手

- `首位打者`
- `本塁打王`
- `盗塁王`
- `打点王`
- `最高出塁率`

#### 投手

- `最多セーブ`
- `最優秀中継ぎ`
- `最多奪三振`

#### 互換性・将来対応

- `最多勝`
- `最優秀防御率`

これらは従来の部門タイトルと同じ扱いとし、1件につき次を加算すること。

```text
評価点: +160
部門タイトル数（king）: +1
```

部分一致による誤判定を避けるため、可能であれば定数配列または専用ヘルパー関数で管理すること。

### 4.2 最優秀投手賞をリーグ別に保存・集計する

受賞記録へ対象リーグ名を付けること。

例:

```javascript
h.push(`${y} ${lgN}最優秀投手賞`);
```

`honorScore(bucket)` では、対象リーグの受賞記録であることを確認してから次を加算すること。

```text
評価点: +460
最優秀投手賞数（aceN）: +1
```

KBOの受賞をNPB・MLB・CPBLへ、NPBの受賞をKBO・MLB・CPBLへ加算してはならない。

### 4.3 既存の得点を維持する

今回の対象外である次の得点・判定は変更しないこと。

- 年間MVP: `+420`
- 最優秀投手賞: `+460`
- 新人王: `+140`
- ゴールデングラブ賞: `+300`
- 年間最優秀守備選手: `+220`
- 部門タイトル: `+160`
- オールスター選出（野手）: `+40`
- オールスター選出（投手）: `+70`
- リーグ優勝関連の現行得点
- フランチャイズ関連の現行得点
- キャリア通算成績の `careerScore(st)`
- 各リーグの `TIER_TH`
- 殿堂入りに必要な得票率75%と投票演出

### 4.4 国際大会の扱いは変更しない

ユーザー確認済み仕様として、国際大会実績はKBO・CPBL・MLBの殿堂評価へ加算しない。

次の現行処理は維持すること。

```javascript
if(bucket==='NPB'){
  // intlCount およびWBC・WBSCプレミア12の結果加算
}
```

今回の修正を理由に、国際大会の加点対象リーグを広げてはならない。

## 5. 守田巧の再計算確認

確認に使用したKBO通算成績:

- 13年
- 1703試合
- 7239打席
- 1927安打
- 216本塁打
- 972打点
- 89盗塁
- 守備貢献 `+64`

- KBO首位打者 4回
- KBO打点王 3回
- KBO本塁打王 2回
- KBO最高出塁率 2回
- KBOオールスター 6回

修正前:

```text
評価点 6671
KBO殿堂基準 8200

```

漏れていた6タイトルを加算:

```text
首位打者4回 × 160 = 640
最高出塁率2回 × 160 = 320

```

```text
6671 + 960 = 7631
KBO殿堂基準まで 569不足
評価区分は引き続き「KBOスター選手」
殿堂入りはしない
```

国際大会成績はKBO評価へ加算しないこと。

## 10. 年俸表示文言の修正

### 10.1 修正理由

次年度の所属先が確定してから来季年俸を決定する仕様であるため、シーズン終了時点で「次年度年俸：オフシーズン確定後」と表示する必要はない。

また、スポーツゲームの表示として `次年度年俸` は事務的で違和感があるため、`来季年俸決定` へ変更する。

### 10.2 シーズン終了カード

カードタイトルは現行のまま維持する。

```text
シーズン終了
```

現在の本文:

```text
今季支給年俸：{今季年俸}｜次年度年俸：オフシーズン確定後｜生涯収入：{生涯収入}
```

修正後:

```text
今季支給年俸：{今季年俸}｜生涯収入：{生涯収入}
```

具体的には、`phaseEnd` 内の次の表示から `｜次年度年俸：オフシーズン確定後` を削除すること。

```javascript
card('','シーズン終了',`今季支給年俸：<b class="hl">${fmtMoney(paid)}</b>｜次年度年俸：オフシーズン確定後｜生涯収入：${fmtMoney(S.careerEarnings)}`);
```

修正後の想定:

```javascript
card('','シーズン終了',`今季支給年俸：<b class="hl">${fmtMoney(paid)}</b>｜生涯収入：${fmtMoney(S.careerEarnings)}`);
```

### 10.3 所属先確定後の年俸カード

現在のカードタイトル:

```text
次年度年俸
```

修正後:

```text
来季年俸決定
```

現在の本文:

```text
オフシーズンの所属先確定後、次年度年俸は{年俸}に決まった。
```

修正後:

```text
所属先の確定に伴い、来季の年俸は{年俸}となった。
```

`finalizePendingOffseasonSalary()` の表示を次の内容へ変更すること。

```javascript
card('info','来季年俸決定',`所属先の確定に伴い、来季の年俸は<b class="hl">${fmtMoney(S.currentSalary)}</b>となった。`);
```

### 10.4 昇格時の表示

`applyPromotionSalary()` にも `次年度年俸` という同じカードタイトルが存在するため、表示用語を統一すること。

カードタイトル:

```text
来季年俸決定
```

本文:

```text
昇格後の所属レベルを基準に再計算し、来季の年俸は{年俸}となった。
```

想定コード:

```javascript
card('info','来季年俸決定',`昇格後の所属レベルを基準に再計算し、来季の年俸は<b class="hl">${fmtMoney(S.currentSalary)}</b>となった。`);
```

年俸の計算式、受賞ボーナス、減俸防止、契約年数、FA、昇格・降格処理は変更せず、表示文言だけを変更すること。

### 10.5 年俸表示テスト

最低限、次を確認すること。

1. シーズン終了カードに `次年度年俸：オフシーズン確定後` が表示されない。
2. シーズン終了カードには今季支給年俸と生涯収入が表示される。
3. 所属先確定後のカードタイトルが `来季年俸決定` になる。
4. 本文が `所属先の確定に伴い、来季の年俸は～となった。` になる。
5. 昇格時もタイトルが `来季年俸決定` になり、本文で `来季の年俸` を使用する。
6. 年俸計算結果は文言修正前後で変化しない。
