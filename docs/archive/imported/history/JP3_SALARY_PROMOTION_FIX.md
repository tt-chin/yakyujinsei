# JP3 年俸 Bug 修正指示：昇格後に年俸が下がる問題

対象：

`jp3-modularization`

主な対象ファイル：

`docs/src/engine/game.js`

## 現象

NPB二軍所属選手がシーズン終了後にNPB一軍へ昇格した場合、

例：

```text
今季支給年俸：1,600万円
次年度年俸：590万円
```

と表示された後、

```text
アップグレードの通知
NPB一軍へ昇格
```

となる。

結果としてNPB一軍へ昇格したにもかかわらず、
次年度年俸がNPB二軍基準の590万円になる。

## 原因

現在の `phaseEnd()` が `movement()` より前に、

```js
S.currentSalary =
  Math.round(
    salaryFor(S.lv,S.lastD||0) * dpMult() / 10000
  ) * 10000;
```

を実行している。

この時点ではまだ `S.lv` が `NPB2` のため、
次年度年俸がNPB二軍基準で計算される。

その後 `movement()` 内で、

```js
S.lv = to;
```

により `NPB1` へ昇格しても、
`S.currentSalary` が再計算されない。

そのため、

```text
旧レベルで次年度年俸計算
↓
昇格
↓
旧レベル年俸のまま
```

となっている。

## 修正方針

単純にNPB一軍だけを特別処理しないこと。

NPB / KBO / CPBL / MiLBを含む、
すべての同一組織内の昇格・降格に対応できる共通処理にする。

基本ルール：

### 昇格

同一組織内で上位レベルへ昇格した場合：

```text
次年度年俸 =
max(
  昇格前に保持している年俸,
  salaryFor(昇格後レベル, lastD) × 契約係数 × 守備係数
)
```

つまり、

**昇格による減俸は禁止。**

新しい所属レベルの給与計算額が現在年俸より高ければ、
新レベル側の年俸を採用する。

### 降格

降格については既存の契約・戦力外・契約更改仕様を壊さないこと。

「昇格時に年俸が下がらない」修正を理由に、
降格時まで無条件で旧年俸を保証しない。

既存の契約保証・buyout・FAロジックを維持する。

## phaseEnd の修正

現在の `phaseEnd()` では、
movement前に「次年度年俸」を確定させている。

この設計を修正する。

シーズン終了時点では原則として：

```text
今季支給年俸
生涯収入
```

のみ確定表示する。

まだその後に、

- 昇格
- 降格
- 契約更改
- FA
- 戦力外
- 海外移籍
- 日本球界復帰

が発生する可能性があるため、
movement前に確定的な「次年度年俸」を表示しないこと。

**次年度年俸は、昇格・降格・FA・移籍などオフシーズンの所属先が確定した後にのみ表示・確定すること。**

必要であれば、

```text
次年度年俸：オフシーズン確定後
```

のような表示に変更してよい。

## 昇格処理

現在の、

```js
S.lv=to;
card(...);
board(2);
```

だけで終わる処理を修正する。

昇格前レベルを保持：

```js
const fromLv = S.lv;
```

昇格後：

```js
S.lv = to;
```

とした後、
共通の年俸更新処理を呼ぶ。

例として、

```js
function applyPromotionSalary(fromLv,toLv){
   ...
}
```

のような共通関数を作成してよい。

ただし関数名・配置は既存構造に合わせて判断すること。

## 契約情報との整合性

`S.currentSalary` だけ変更して終了しないこと。

`S.ct` が存在する場合は必要に応じて：

```js
S.ct.annualSalary
S.ct.totalValue
```

など現在使用されている契約情報とも整合性を取る。

ただし残契約年数やFA取得条件を意図せず変更しないこと。

## 期待例

NPB二軍：

```text
現在年俸：1,600万円
lastD = 3
```

からNPB一軍へ昇格する場合、

現在の `salaryFor('NPB1',3)` に従い、
次年度年俸を再計算する。

少なくとも：

```text
次年度年俸 < 1,600万円
```

には絶対にならないこと。

具体的な値は既存 `salaryFor()` の公式を使用する。

## 他リーグも確認

