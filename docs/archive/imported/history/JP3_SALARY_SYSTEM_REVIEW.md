# JP3 Salary System Review

対象ブランチ：`jp3-modularization`

主な対象ファイル：
- `docs/src/engine/game.js`
- `docs/src/engine/salary-promotion-policy.js`
- 必要に応じて関連テストファイル

## 目的
現在の年俸システムについて、単発のBug修正だけでなく、NPB / KBO / CPBL / MLB の年俸バランス、契約更新、昇格、FA、年度賞の影響まで含めて全面的に見直す。

今回の目的は以下の2段階とする。
1. 既知Bugの修正
2. 年俸システム全体の妥当性レビューと必要最小限の調整

## 1. 既知Bug：延長契約後に年俸が下がる
例：
```text
今季支給年俸：6,400万円
年間賞：NPBオールスターゲーム｜最優秀投手賞
契約更新を延長する
追加2年（年俸係数×1.34）
```
にもかかわらず、
```text
次年度年俸：4,000万円
```
になる。

原因：
`phaseEnd()` で先に `pendingOffseasonSalary` を計算しているが、その後 `extensionOffer()` により `S.ct.mult` が変更されても、`pendingOffseasonSalary` が再計算されていない。

修正要件：
- 契約延長・契約更改などで契約係数が変わった場合、最終確定前に新しい契約条件を反映して次年度年俸を再計算する。
- `pendingOffseasonSalary` を固定値として早期確定しない。

## 2. 球団主導の延長契約で減俸させない
原則減俸禁止：
```text
同一球団での昇格
球団から提示された延長契約
球団から提示された契約更新
```

基本ルール：
```text
newSalary = max(
  currentSalary,
  recalculatedSalaryAfterContract
)
```

減俸を許容：
```text
降格
戦力外
FA市場でオファーなし
宣言残留の減額契約
明示的な減俸イベント
```

## 3. NPB年俸計算の再確認
現在の一軍年俸テーブル：
```js
NPB1:[
  16000000,
  4000000,
  3000000,
  16000000,
  600000000
]
```

現在の概念：
```text
基本年俸
+ d × 線形加算
+ d>7 の二次加算
```

現状では年度賞そのものが `salaryFor()` に直接影響しない。
そのため、
```text
12勝
ERA 3.05
最優秀投手賞
```
のようなシーズンでも、`d` が十分高くなければ年俸が伸びにくい。
この設計が妥当か再評価すること。

## 4. 四リーグの年俸曲線を比較する
対象：
```text
NPB1
KBO1
CPBL1
MLB
```

`d = 0 ～ 20` について `salaryFor(lv, d)` の結果を一覧化する。

最低限比較：
- 基本年俸
- d=0
- d=3
- d=5
- d=7
- d=8
- d=10
- d=12
- d=15
- d=20
- 上限額への到達難易度

レビュー観点：
- NPBだけ不自然に伸びにくくないか
- KBO / CPBLとの差が妥当か
- MLBとの差が極端すぎないか
- d>7 の二次加算開始位置が適切か

## 5. 年度賞を年俸評価へ反映する案を検討
投手：
```text
年間MVP
最優秀投手賞
沢村賞相当
最多勝
最優秀防御率
最多奪三振
最多セーブ
最優秀中継ぎ
```

野手：
```text
年間MVP
首位打者
本塁打王
打点王
最高出塁率
盗塁王
ゴールデングラブ賞
年間最優秀守備選手
```

固定額加算に限定せず、
```text
salaryScoreBonus
awardMultiplier
effectiveDBonus
```
など、既存設計と整合しやすい方法を選ぶこと。

## 6. 推奨する基本方針
```text
leagueBaseSalary
+
performanceValue(d)
+
awardValue
+
starValue
```
その後、
```text
contractMultiplier
positionMultiplier
```
を適用する。

可能なら、
```text
salaryFor()
+ salaryAwardAdjustment()
+ contractMultiplier
```
のように責務を分ける。

## 7. 年度賞の影響ルール
MVP / 最優秀投手級で同一球団更新の場合：
```text
newSalary >= currentSalary
```
を保証。

主要タイトルは年俸評価へ何らかの加点を与える。ただし賞の乱獲で指数関数的に暴騰しないよう上限を設ける。

## 8. 先発・中継ぎ・抑え・野手の公平性
最低限：
```text
先発投手
セットアッパー
クローザー
野手
```
で、同程度のリーグ内トップクラス成績を残した場合に年俸成長が極端に不公平にならないか確認する。

## 9. 契約更新タイミングの整理
次年度年俸は以下の順序で決める：
```text
シーズン終了
↓
今季支給年俸確定
↓
年間賞確定
↓
昇格・降格
↓
契約延長 / FA / 移籍 / 残留
↓
最終所属先・契約条件確定
↓
次年度年俸確定
```

`phaseEnd()` 時点で最終額を固定しない。

表示：
```text
次年度年俸：オフシーズン確定後
```
は維持してよい。

## 10. 期待する実例
### ケースA
```text
NPB1
今季年俸：6,400万円
12勝7敗
ERA 3.05
最優秀投手賞
球団から2年延長
契約係数×1.34
```
期待：
```text
次年度年俸 < 6,400万円
```
にはならないこと。契約係数1.34が実際の最終年俸へ反映されること。

### ケースB
```text
NPB2 → NPB1昇格
```
期待：
```text
昇格後年俸 >= 昇格前年俸
```

### ケースC
```text
NPB1
成績不振
FA市場オファーなし
```
これは減俸を許容。

### ケースD
```text
NPB1
主要タイトル受賞
同一球団残留
```
主要タイトルが年俸評価へ反映されること。
