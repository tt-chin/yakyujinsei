# 野球人生シミュレーター 移植機能実装スケジュール

## 1. 文書情報

- 対象：日本語版「野球人生シミュレーター」
- 現行基準：`1.4.5`
- バージョン表記：`x.x.x`
- 上位仕様：`YaKyoLife_詳細設計書.md`
- 差分仕様：`MIGRATION_MASTER_SPEC.md`
- 完了確認：ユーザー確認によりv1.4.5の実装完了（2026年9月4日）
- 作成日：2026年8月29日
- 再策定日：2026年9月4日
- 目的：残存機能を相互影響の少ない単位に分け、設計、実装、回帰、公開の順序を固定する

本書は`MIGRATION_MASTER_SPEC.md`の実装順を具体化する。バージョン順序について差異がある場合は、本書を最新の計画として扱う。ただし、ゲーム仕様は常に`YaKyoLife_詳細設計書.md`を優先する。

## 2. バージョン運用

|変更種別|版番号例|扱い|
|---|---|---|
|現行完了基準|`1.4.5`|NPB復帰・海外オファー年俸表示と越境年俸回帰を完了|
|新機能群|`1.5.0`、`1.6.0`|中位番号を上げる|
|公開後の不具合修正|`1.5.1`、`1.5.2`|当該機能版の修正だけ|
|緊急表示修正|同一系列の末位番号|新機能を混在させない|

新機能を末位番号の更新へ追加しない。たとえば`1.5.1`は`1.5.0`の不具合修正専用とする。

v1.0.4～v1.4.5は薪資・契約構造、選択UI、契約更新・例外復旧、越境オファー表示の改修として完了済みである。本書の旧予定版`1.1.0～1.4.0`は使用済みのため、移植機能は`1.5.0`から再開する。

## 3. 設計判定

|判定|意味|実装開始条件|
|---|---|---|
|直接実装可|Masterの条件と現行仕様で判断可能|Codexがコード調査と実装計画を提出し、承認後に実装|
|補充設計必要|機能方向は確定しているが、対応表・token・状態境界が不足|補充設計書を完成し、未決事項をゼロにしてから実装|
|個別詳細設計必須|ゲーム状態、記録、判定、RNGまたは生涯結果へ影響|専用詳細設計と受入テストを承認してから実装|

## 6. 各版の開始条件

各版は次をすべて満たしてから実装を開始する。

1. 対象となる補充設計または詳細設計が完了している
2. 未決事項が列挙され、実装を左右する項目が解決済みである
3. 現行コードの対象関数、DOM、状態キーが確認済みである
4. 変更予定ファイルと変更しないファイルが明示されている
5. RNG消費の有無が明示されている
6. 固定seed比較項目が決まっている
7. PC・モバイルE2E項目が決まっている
8. 公開前Preview環境で確認できる

## 7. 各版の完了条件

1. 対象外機能を同時実装していない
2. `VERSION`が予定版と一致する
3. seed-only URLを維持する
4. UIだけの版では固定seed結果とRNG消費回数が完全一致する
5. 状態追加版では対象外の固定seed差分がない
6. JavaScript構文、import/export、CSS参照に問題がない
7. Consoleエラー、JavaScript 404、CSS 404がない
8. PC・モバイル主要操作が完了する
9. Preview確認後にのみ正式公開する
10. `YaKyoLife_詳細設計書.md`とCHANGELOGを更新する

### 7.1 v1.4.5完了記録

ユーザー確認によりv1.4.5は完了済みである。実装時の詳細なテスト結果は同版のCodex完了報告を正本とし、以下を以後の回帰基準として維持する。

1. KBO、CPBL、MiLB、MLBからのNPB復帰オファーに対象階層と年俸が表示される
2. 表示年俸と契約後の`S.ct.annualSalary`、`S.currentSalary`が一致する
3. NPB一軍からCPBL一軍への年俸は既存の`par`換算を一度だけ適用する
4. 現在の固定契約年俸と移籍先の新規市場年俸を別の値として扱う
5. 年俸曲線、リーグ基準、海外契約係数、為替仕様を変更しない
6. 候補表示時にRNGを追加消費しない
7. 契約年数の`ri(1,3)`を選択前へ移動しない

## 8. 同時実装禁止

- UI基盤と大会別国際記録の状態追加
- 初回テーマ導入とCanvas共有画像改修
- 故障リスク表示と故障確率変更
- イベント分類とイベント抽選方式変更
- 背番号と永久欠番
- 新機能と無関係なリファクタリング

## 9. 進捗更新規則

- 設計資料完成時：本書のD番号を「完了」にする
- 実装計画承認時：対象版を「実装待ち」にする
- 実装中：対象版だけを「実装中」にする
- Preview検証完了時：「公開待ち」にする
- 正式公開時：「完了」と公開日を記録する
- 差異が一件でもある場合：「完了」にしない
