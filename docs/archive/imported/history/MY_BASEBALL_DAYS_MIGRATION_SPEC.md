# 「野球之旅 My Baseball Days」参考機能 移植仕様書

## 1. 文書情報

- 対象作品：日本語版「野球人生シミュレーター」
- 現行基準バージョン：`1.0.3`
- 参考サイト：`https://mbday.myz.tw/`
- 参考時点：2026年8月28日
- 参考サイト確認バージョン：v2.7.6
- 文書種別：将来バージョン向け移植・改善仕様
- 実装状態：未実装。機能ごとに実装対象バージョンを決定してから着手する

本書は「野球之旅 My Baseball Days」で確認できた設計のうち、日本語版「野球人生シミュレーター」の操作性、情報の分かりやすさ、モバイル体験を改善できる要素を整理し、日本向け仕様として再設計するための移植仕様書である。

参考サイトのコード、文章、画像、台湾固有データをコピーすることを目的としない。採用するのは設計思想とユーザー体験であり、実装は日本語版の既存コード、既存状態、既存ゲーム規則に合わせて独自に行う。

## 2. バージョン表記方針

### 2.1 統一ルール

旧来の`JP3`、`JP4`などの名称は今後使用しない。

すべての公開バージョン、設計書、修正書、画面表示、定数、更新履歴、テスト結果は次の3桁形式で統一する。

```text
x.x.x
```

現在の最新版は次のとおりとする。

```text
1.0.3
```

### 2.2 バージョンアップ基準

| 種類 | 例 | 用途 |
| --- | --- | --- |
| パッチ | `1.0.3` → `1.0.4` | 不具合修正、表示修正、既存仕様内の小調整 |
| マイナー | `1.0.3` → `1.1.0` | 後方互換性のある新機能、UI追加、設定追加 |
| メジャー | `1.x.x` → `2.0.0` | 保存形式、主要ゲームフローなどの互換性を壊す変更 |

複数の機能をまとめて実装する場合でも、変更内容に応じて上記基準で番号を決定する。将来版を一律に`JP4`と呼ばない。

### 2.3 コード内定数

現在コード内に`RULES_VERSION = "JP3"`など旧名称が残っている場合は、別の修正作業として影響範囲を調査する。本書の機能移植と同時に無条件で変更してはならない。

URL、seed再現、保存データ、回帰テストが旧定数に依存している可能性があるため、定数変更は専用の移行仕様とテストを用意して実施する。

## 3. 移植の基本原則

### 3.1 採用対象

日本語版へ採用する候補は次の領域に限定する。

- 情報を役割別に整理する画面構成
- モバイルで操作しやすいナビゲーション
- 能力、潜在能力、健康、契約条件の可視化
- 育成ポイントを素早く分配する操作
- 契約、配置転換、ケガなどの理由説明
- ブラウザ内保存と読込
- 深色／明色テーマ、文字サイズなどの表示設定
- 更新履歴と初心者向け説明
- 表示内容と内部処理を一致させる設計原則

### 3.2 移植しないもの

次は台湾固有仕様または日本語版の確定仕様と競合するため、直接移植しない。

- CPBL固有の球団、リーグ強度、球季数、賞の基準
- 台湾の高校、大学、社会人、独立リーグ固有データ
- 台湾のドラフト資格、旅外、帰国、国際大会選考規則
- 台湾代表の大会別競争力補正
- 台湾固有の事件、人物名、ネット用語、通貨表現
- LINEコミュニティ誘導ポップアップ
- 参考サイトの文章、画像、ロゴ、CSS、JavaScriptのコピー
- 「同じseedならゲーム更新後も永久に同一結果」と保証する説明

### 3.3 既存仕様の優先

移植時は日本語版`1.0.3`の次の仕様を優先する。

- seed-only URL
- 現在のRNGアルゴリズム
- RNG消費順
- 現在の日本リーグ階層と強度
- 現在の成績、年俸、契約、昇降格、移籍、引退、殿堂判定
- 日本語表示と日本向け用語
- GitHub Pagesでビルド不要の配信方式

UI表示処理、保存処理、設定処理から新しい乱数を消費してはならない。

## 5. 機能別詳細仕様

## 5.1 4タブ情報構成

### 目的

現在の単一画面に集中している情報を役割別に整理し、イベントカードと選択肢を読みやすくする。

### タブ名称

```text
ホーム
育成
シーズン
選手記録
```

`ファイル`は使用しない。日本のゲーム画面では意味が曖昧なため、選手の経歴と成績を扱う画面は`選手記録`とする。

### 各タブの責務

| タブ | 表示内容 |
| --- | --- |
| ホーム | 現在のイベント、主要選択肢、選手名、所属、年齢、年度、総合、現在年俸 |
| 育成 | 能力値、潜在能力、配分可能ポイント、健康状態、ケガリスク、守備位置・投手役割 |
| シーズン | 本季目標、現在フェーズ、当季成績、球団評価、次のキャリア分岐、チーム状況 |
| 選手記録 | 年度別成績、受賞歴、所属履歴、契約履歴、国際大会、通算成績 |

### PC表示

- 上部または左側にタブナビゲーションを表示する。
- イベントカードと選択肢を主領域に残す。
- 画面遷移でゲーム状態を再計算しない。
- タブ切替でRNGを呼び出さない。

### モバイル表示

- 画面下部に固定ナビゲーションを配置する。
- 端末のsafe-areaを考慮する。
- 下部ナビゲーションが選択ボタン、結果カード、共有ボタンを隠さないよう余白を確保する。
- 360px幅を最低検証幅とする。

### 受入条件

- 4タブ間を移動しても選択中のイベントと未確定配分が失われない。
- 表示順以外のゲーム結果が導入前と一致する。
- 戻る操作で意図しないゲーム進行が起きない。
- PCとモバイルの両方で横スクロールが発生しない。

## 5.3 育成ポイント高速配分

### 操作

各能力に次の操作を用意する。

```text
+1
+5
全投入
```

画面全体には次を追加できる。

```text
均等配分
配分を元に戻す
確定
```

### 仕様

- `+5`は残りポイントが5未満の場合、残量のみ投入する。
- `全投入`はその能力の上限を超えない。
- `均等配分`は対象となる成長可能能力だけへ配分する。
- 端数の配分順序は固定し、RNGを使用しない。
- `配分を元に戻す`は今回の配分だけを戻し、過去年度の確定能力を変更しない。
- 確定前に現在値、潜在能力、投入後の値を表示する。
- 既存の1点ずつ配る操作も維持する。

### RNG条件

現在の育成方式にサイコロ結果やランダム成長が含まれる場合、ボタンは既に確定した配分可能量を操作するだけとする。ボタン操作時に新しい乱数を消費してはならない。

### テスト

- 残り3点で`+5`を押す。
- 潜在上限直前で`全投入`を押す。
- 複数能力で均等配分し端数が出る。
- 元に戻してから再配分する。
- 投手、捕手、内野手、外野手で対象能力が正しい。

## 5.4 能力値／潜在能力の可視化

### 表示例

```text
ミート　52 / 68
████████░░
```

### 要件

- 左側を現在値、右側を潜在上限とする。
- 色だけで状態を伝えず、必ず数値も表示する。
- 上限到達時は`上限到達`と表示できる。
- ケガや一時補正がある場合、基礎値と一時補正を混同しない。
- 投手と野手で存在しない能力を表示しない。
- 野手の総合計算に体力を含める`1.0.3`仕様と、表示上の能力一覧が一致していることを確認する。
- 投手の総合計算方式は既存仕様を維持する。

## 5.5 契約条件の比較表示

### 目的

成績が良いのに減俸される、FAオファーが現年俸より低い、海外から日本へ戻る際に年俸が分からない、といった不自然さや説明不足を解消する。

### 契約カード必須項目

```text
球団名
所属リーグ／階層
契約年数
提示年俸
前年年俸
前年比（増減額・増減率）
契約区分
想定される役割
提示理由
```

### 表示例

```text
提示年俸：4,800万円
前年年俸：4,200万円
前年比：+600万円（+14.3%）
評価理由：一軍での安定した出場実績と今季成績を評価
```

### 評価理由候補

- 当季成績
- 直近複数年の実績
- 一軍／二軍／育成などの所属階層
- 年齢と将来性
- ケガ、手術、長期離脱
- 受賞歴
- FA市場の競争数
- 球団内で期待される役割
- リーグ間の年俸水準差

### 契約ロジック原則

- 複数球団が競合するFAでは、母球団が必ず機械的に減俸提示する仕様にしない。
- 他球団から現年俸未満の提示が出る場合、年齢、ケガ、役割、リーグ差など合理的理由を表示する。
- 理由が存在しない低額提示は表示上の問題ではなく計算ロジックの不具合として扱う。
- 海外所属中に日本復帰契約を提示するときも、決定前に日本での年俸を表示する。
- 比較画面の金額と契約確定後の実際の年俸を一致させる。
- `戻って再検討`操作で報価を再抽選しない。同じ交渉状態では同じ提示を再表示する。

### 受入条件

- 全オファーに金額、年数、役割が表示される。
- 現年俸と比較できる。
- 日本復帰、海外移籍、FA、残留、戦力外後の再契約で表示形式が統一される。
- 球団名が長い場合も金額や成績欄がずれない。

## 5.6 表示と実際の処理の一致

### 原則

選択肢の文言は、実際の遷移先と同じデータから生成する。固定文言と遷移ロジックを別々に管理しない。

### 必須確認例

- 海外在籍中の日本復帰を`海外移籍オファー`と表示しない。
- NPB育成所属者に`二軍降格`を表示しない。
- 総合30未満で強制引退する選手に、降格・再起・再契約選択肢を表示しない。
- 移籍確定後は新しい所属球団名を表示する。
- 契約カードの年俸と確定後の状態値を一致させる。
- 守備位置変更の説明と実際に変更される守備位置を一致させる。

### 実装指針

遷移先、契約種別、所属階層、表示ラベルをまとめた結果オブジェクトを作り、UIはそのオブジェクトを描画する。UI側で所属先や契約種別を再判定しない。

## 5.7 健康状態とケガリスク詳細

### 表示項目

```text
現在のケガリスク：12%
```

内訳例：

```text
年齢　　　　　+3%
体質　　　　　+2%
今季の疲労　　+5%
過去の大ケガ　+4%
休養　　　　　-2%
```

### 要件

- 表示値は既存のケガ判定に使用する値から算出する。
- 表示のために判定を再抽選しない。
- 投手の肘負荷や手術履歴が独立管理されている場合、一般ケガリスクと分けて表示する。
- リスク値と実際の判定式が異なる場合、推定値であることを明示する。
- 守位ごとにケガの説明文を変える場合、日本野球の自然な場面へ書き換える。

## 5.8 守備位置・投手役割変更の説明

### 変更前に表示する内容

- 球団または指導者が変更を提案する理由
- 変更後の守備位置または投手役割
- 受け入れた場合の効果
- 拒否した場合の影響
- 一時的変更か恒久的変更か

### 選択肢例

```text
配置転換を受け入れる
現在のポジションで勝負する
詳細を確認する
```

拒否を選べる場合、拒否後の出場機会、球団信頼、失策リスクなど実際に発生する影響を事前に表示する。

## 5.9 ブラウザ保存／読込

### 目的

長期間の生涯を途中で中断し、同じ端末で再開できるようにする。

### 保存対象

- 状態`S`の必要項目
- seed
- RNG内部状態または再開に必要なRNG情報
- 現在フェーズ
- 未確定イベントと選択肢
- 所属、能力、成績、年俸、契約
- 履歴、受賞、ケガ、恋愛、国際大会
- 保存形式バージョン
- ゲームバージョン
- 保存日時

### 保存してはならないもの

- DOM要素
- 関数
- 一時的な表示キャッシュ
- 再生成可能な装飾情報
- 個人情報や外部認証情報

### 保存スロット

初回導入は次のどちらかを選択する。

1. 自動保存1件＋手動保存1件
2. 手動保存3件

仕様決定前に両方を同時実装しない。

### 互換性

保存データに次を持たせる。

```json
{
  "saveVersion": 1,
  "gameVersion": "1.0.3"
}
```

ゲームバージョンと保存形式バージョンを混同しない。将来のゲーム更新で保存構造を変更するときは、明示的なmigration関数を用意する。

### seed-onlyとの関係

- 共有URLは引き続き`?seed=<SEED>`とする。
- 保存データをURLへ埋め込まない。
- seed共有と途中保存は別機能として扱う。
- 保存読込後に現在URLへ不要な状態パラメータを追加しない。

### エラー処理

- データ破損
- 未対応の保存形式
- 必須キー不足
- 容量超過
- ブラウザ保存不可

上記の場合、ゲームを壊さず自然な日本語で説明する。壊れた保存データを自動上書きしない。

## 5.10 テーマと表示設定

### テーマ

```text
ライト
ダーク
端末設定に合わせる
```

現在の濃い赤を日本語版の主色として維持する。参考サイトの色をコピーしない。

### 文字サイズ

```text
小
標準
大
```

または75%～125%の範囲で段階設定する。ゲーム進行ボタン、表、長い球団名、年俸金額が崩れないことを優先する。

### 保存

テーマと文字サイズはゲーム状態とは別に端末へ保存する。新しい野球人生を開始しても表示設定は維持する。

### アクセシビリティ

- 色だけで成功、失敗、増額、減額を区別しない。
- 本文と背景のコントラストを確保する。
- ボタンのタップ領域を十分確保する。
- フォーカス表示を消さない。
- 文字拡大時にも操作不能にならない。

## 5.11 初心者向け説明

### 対象

- ワールドシードとは何か
- 同じseedと同じ選択の意味
- ゲーム更新後の完全再現を保証しないこと
- ポジションごとの主要能力
- 総合評価の意味
- 育成ポイントの使い方
- 所属階層と昇降格
- 契約と年俸
- 保存と共有の違い

### 表現方針

短い説明を基本とし、詳細は`詳しく見る`で開く。ゲーム開始時に複数の長いポップアップを連続表示しない。

seed説明には次を明記する。

```text
同じバージョン、同じseed、同じ選択では同じ結果を再現できます。
ゲーム更新後の完全な再現は保証されません。
```

- 受賞、国際大会、通算成績の整理
- 引退理由に応じた演出差

### 引退理由別演出

- 自主引退
- 契約満了
- 戦力外
- オファーなし
- 総合30未満の強制引退
- ケガによる引退

戦力外やオファーなしでの引退に、必ず盛大な引退試合が開催されたような演出を付けない。長期一軍実績、同一球団年数、功績など既存条件に合わせる。

### 技術条件

- Canvas描画と通常画面の文字を一致させる。
- 画像生成時にRNGを消費しない。
- 画像生成を繰り返してもゲーム状態を変更しない。
- PC／モバイルの両方で保存または共有できることを確認する。

## 6. 日本版向けに再設計すべき参考思想

## 6.1 表彰判定

参考思想として、単純な固定確率ではなく次の2段階を検討する。

1. 出場数、規定到達、成績などで候補資格を判定
2. 資格到達後、リーグ内での支配度に応じて受賞確率を計算

ただし、NPB、MLB、KBO、独立、社会人、高校、大学では試合数と賞の性質が異なる。台湾版の門檻やリーグ補正を移植せず、日本語版の既存値を基準に別途バランス仕様を作る。

## 6.2 ケガ中のイベント整合性

長期離脱またはシーズン終了状態の選手には、試合出場中であることを前提としたイベントを出さない。

代替イベント候補：

- リハビリ計画
- 復帰時期の調整
- チームメイトからの連絡
- 球団との面談
- フォーム再構築
- 二軍施設での調整

イベント追加はRNG消費順を変えるため、通常の表示改善と同時に実装せず、独立したバージョンと固定seed試験を用意する。

## 6.3 国際大会選考

能力値が1点違うだけで必選と落選が切り替わる固定境界ではなく、段階的確率を検討できる。

ただし、日本代表の大会資格、開催周期、プロ・アマの参加条件は日本版仕様として別途定義する。参考サイトの台湾代表補正を使用しない。

## 6.4 引退理由の分岐

引退処理と引退演出を分離し、引退理由を状態として保存する。

```text
voluntary
released
no_offer
overall_below_minimum
injury
age_or_decline
```

内部キーは現行コード規約に合わせて調整する。表示文、結果画像、称号、引退試合の有無はこの理由と功績から決定する。

## 11. 最終方針

本移植で優先すべきなのは、参考サイトを外見ごと再現することではない。

日本語版で既に発生している「理由が分からない」「表示と結果が違う」「スマートフォンで情報が詰まる」「何度もボタンを押す必要がある」といった問題を、次の順序で解決する。

1. 理由を表示する
2. 表示と内部処理を一致させる
3. 操作回数を減らす
4. 情報を役割別に整理する
5. 長い生涯を保存・再開できるようにする
6. その後にゲーム規則そのものの改善を検討する

この順序により、現行`1.0.3`のゲーム結果を不用意に変更せず、将来の`1.0.4`、`1.1.0`、`2.0.0`へ段階的に発展できる構成とする。
