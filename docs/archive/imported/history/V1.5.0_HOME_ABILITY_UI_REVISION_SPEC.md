# v1.5.0 ホーム・能力画面構成 修正仕様書

## 1. 文書情報

- 対象作品：日本語版「野球人生シミュレーター」
- 対象版：`1.5.0`
- 修正時期：正式公開前
- 修正種別：UI情報構造・画面遷移修正
- 上位仕様：`YaKyoLife_詳細設計書.md`
- 関連仕様：`MIGRATION_MASTER_SPEC.md`
- 関連日程：`MIGRATION_IMPLEMENTATION_SCHEDULE.md`
- 基礎設計：`UI_FOUNDATION_SUPPLEMENTAL_DESIGN.md`

`1.5.0`は正式公開前であるため、本修正を`1.5.0`へ含める。版番号を`1.5.1`へ変更しない。

## 2. 背景と不具合

現在のPreview実装では、イベント選択肢が「育成・行動」、イベント結果が「ホーム」に分かれている。

この構成では、利用者がイベントを選択しても結果を直ちに確認できず、手動で「ホーム」へ切り替える必要がある。選択と結果確認が分断され、次に何が起きたか分かりにくい。

原因は、`#act`と`#log`を別のメイン領域へ配置したこと、および選択実行後の結果確認を優先する画面遷移が定義されていないことである。

## 3. 修正方針

操作・選択肢と結果・進行履歴を「ホーム」に統合する。旧「育成・行動」は廃止し、そのナビゲーション位置を読取専用の「能力」へ変更する。

変更後のメインナビゲーションは次のとおりとする。

```text
ホーム｜能力｜記録｜選手詳細
```

本修正は表示構造の変更だけであり、ゲーム仕様、イベント処理、能力計算、状態`S`およびRNGを変更しない。

- ホームへの`#act-toggle`、`#act`、`#log`の統合
- ホーム内の操作・選択肢と履歴の表示順整理
- 「育成・行動」から「能力」へのナビゲーション変更

- `activeMainView`の値と切替処理の更新
- 旧`action`領域参照の除去

- 高速配分
- 配分前Undo
- 新しい能力比較UI
- 新しい能力値または潜在能力の追加

- ゲーム途中保存
- v1.6.0以降に予定されている機能

## 5. ホーム画面仕様

### 5.1 所有する情報

ホームは次の両方を所有する。

1. 進行中のイベント・操作選択肢
2. イベント結果・ゲーム進行履歴

ホーム内の基本表示順は次のとおりとする。

```text
操作・選択肢（#act-toggle、#act）
↓
最新結果・ゲーム進行履歴（#log）
```

### 5.2 DOM制約

- `#act-toggle`、`#act`、`#log`のIDを変更しない
- 各DOMを複製しない
- 同一IDの要素を作らない
- 既存DOMを`innerHTML = ''`等で破棄しない
- 既存event listenerを維持する
- 選択肢生成処理を二度呼ばない
- `#log`へのカード追加順を変更しない
- 年度折りたたみ等の既存動作を維持する

### 5.3 選択と結果表示

- 新しい選択肢が生成された場合もホームを維持する
- 選択肢実行後もホームを維持する
- 選択実行を理由として別のメイン領域へ自動切替しない
- 結果カードは既存処理どおり`#log`へ追加する
- 続けて次の選択肢が生成された場合はホーム上部へ表示する
- 次の選択肢のDOMとevent listenerを保持する
- 選択肢は一度だけ実行できることを維持する

### 5.4 スクロール

自動スクロールは次の優先順位とする。

1. 選択結果が追加された場合は、最新結果を確認できる位置を表示する
2. 続けて必須選択肢が生成された場合は、その存在が画面内または明確な表示で分かるようにする
3. 新規選択肢だけが生成された場合は、選択肢を確認できる位置を表示する

PC・モバイルの両方で、選択肢と結果の位置関係が分かり、不要な大きな空白や横スクロールが発生しないようにする。

## 6. 能力画面仕様

### 6.1 基本方針

旧「育成・行動」の位置へ、現在の選手能力を確認する読取専用の「能力」領域を設置する。

能力画面は状態`S`に保存済みの値を表示するだけとし、新しい計算、判定、乱数消費および状態変更を行わない。

### 6.2 表示項目

現行ゲームに存在する値の範囲で、最低限次を表示する。

- 総合
- 現在能力値
- 潜在能力上限
- 投手の場合は投手用能力
- 野手の場合は野手用能力
- 現行状態に存在する体力・疲労・故障関連情報

表示項目名、順序、色、数値形式は現行表示を優先する。存在しない能力、状態、評価値を新設しない。

### 6.3 更新方法

- 能力画面を開いた時に現行状態から読取専用表示モデルを生成する
- ホーム側で能力が変化した後、能力画面を再度開くと最新値を表示する
- 再描画によって状態`S`を変更しない
- 再描画によってRNGを消費しない
- 能力画面から能力を変更できない

### 6.4 禁止する操作

- 能力点配分
- `+1`、`+5`、全投入、均等配分等の高速配分
- Undo
- 能力変更ボタン
- 仮想成長結果の計算

高速配分とUndoはv1.6.0の対象とし、本修正へ先行導入しない。ただし、状態にすでに存在する潜在能力上限を既存形式で表示することは可能とする。

## 7. UI状態

メイン領域は次の値で管理する。

```javascript
const uiState = {
  activeMainView: 'home',
  activeDetailTab: 'achievements'
};
```

`activeMainView`で使用可能な値は次のとおりとする。

```text
home
ability
record
player
```

- 旧`action`値を廃止する
- UI状態を状態`S`へ追加しない
- UI状態をURLへ保存しない
- UI状態をseed再現結果へ含めない
- 新規開始および再読込時は`home`から開始する

旧`action`を参照するnavigation、JavaScript、CSS、class、data属性、テストおよび設計書をすべて調査し、不要な参照を残さない。

## 8. RNG・ゲーム状態への影響

- UI操作でRNGを消費しない
- 能力表示で`R()`、`ri()`、`pick()`、`chance()`等を呼び出さない
- イベント選択時の既存RNG呼出順を変更しない
- 選択肢生成回数を変更しない
- 状態`S`の構造を変更しない
- 固定seedのゲーム結果を変更しない

## 9. 変更禁止事項

次を変更してはならない。

- ゲーム仕様およびゲームバランス
- イベント内容、出現順、成功率、効果、選択結果
- 既存表示文および翻訳（今回指定するナビゲーション名を除く）
- RNGアルゴリズムおよび呼出順
- 固定seed結果
- 能力値、潜在能力および計算式
- 薪資、契約、移籍、昇降格
- 故障、TJ、成績計算、表彰、引退、殿堂
- seed-only URL仕様
- 状態`S`の構造
- `RNG_VERSION`およびゲーム規則バージョン
- v1.6.0以降の機能

無関係なリファクタリングを同時に行わない。

### 10.1 ナビゲーション

1. メインナビが`ホーム｜能力｜記録｜選手詳細`になっている
2. 「育成・行動」の表示と旧`action`領域が残っていない
3. ゲーム開始時にホームが表示される
4. メイン領域切替で状態`S`が変化しない
5. メイン領域切替でRNGを消費しない
6. PC・モバイルでナビゲーションが崩れない

### 10.2 ホーム

1. イベント選択肢がホームに表示される
2. 選択実行後もホームのままである
3. 選択結果を直接確認できる
4. 次の選択肢が生成された場合も消失しない
5. 選択肢を一度だけ実行できる
6. event listenerが重複しない
7. ゲーム進行履歴の順序が変わらない
8. 年度折りたたみ等の既存動作が維持される
9. 不要な大きな空白や横スクロールがない

### 10.3 能力

1. 投手の能力項目が正しく表示される
2. 捕手、内野手、外野手の能力項目が正しく表示される
3. 現在能力と既存の潜在上限が現行状態と一致する
4. 能力変化後に再表示すると最新値になる
5. 表示前後で状態`S`が変化しない
6. 表示前後でRNG消費回数が変化しない
7. 能力画面から能力を変更できない

### 10.4 回帰

1. 投手3件、野手3件以上の固定seed比較
2. 初期能力、イベント順、選択結果、年度成績、契約、移籍、引退結果が変更前と一致する
3. RNG消費回数と順序が変更前と一致する
4. seed-only URLが維持される
5. JavaScript構文とimport/exportが正常である
6. JavaScript・CSSの404がない
7. Consoleエラーがない
8. 新規開始から引退まで主要操作が完了する
9. リザルト画像とURLコピーが動作する
