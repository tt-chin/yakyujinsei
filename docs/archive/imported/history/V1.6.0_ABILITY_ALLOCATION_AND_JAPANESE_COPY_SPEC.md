## 1. 実装範囲

### 1.1 必須機能

1. 能力ポイント配分に `+1`、`+5`、`MAX` を追加する。
2. 直前操作を正確に戻せる Undo を維持・拡張する。
3. 現在の配分セッションを初期状態へ戻す「すべてリセット」を追加する。
4. 現在値、潜在値、配分可能ポイント、能力上昇までの進捗を同一画面で確認できる状態を維持する。
5. 全ユーザー向け表示文言を静的・実行時の両面から棚卸しし、不自然な日本語、英語内部値、中国語混入、用語揺れを修正する。
6. 契約画面の `年度schedule` を「年度別年俸」へ変更し、契約種別の内部コードを日本語表示に変換する。

### 1.2 対象外

- 能力値、潜在値、必要ポイント、成長率、衰退率の変更
- 潜在値を能力値の上限へ変更すること
- RNG アルゴリズム、呼出順、消費回数の変更
- 配分確定時に実行される既存の特性判定の変更
- やり直し（Redo）、`-1`、`-5`、長押し連打
- 新イベント、新特性、新リーグ、新しい契約制度
- 到達不能な旧処理の削除や大規模リファクタリング

### 2.1 現行 Undo の注意点

現行処理は能力値、繰越ポイント、残りポイントを復元するが、`touchedKeys` の加算を戻していない。取り消した配分が確定時の集中育成／特性判定に残る可能性があるため、v1.6.0 では Undo と全リセット時に `touchedKeys` も完全復元する。これは新仕様ではなく、表示上取り消した操作を内部状態からも取り消す整合性修正である。

## 3. 能力ポイント配分 UI

### 3.1 対象モード

- `pool` モードのみ `+1`、`+5`、`MAX`、Undo、すべてリセットを表示する。
- `dice` モードは各サイコロが不可分で、割当順が結果に影響するため、現行どおり現在のサイコロを能力へ1個ずつ割り当てる。
- サイコロモードへ `MAX` を追加しない。

### 3.2 1能力行の構成

表示順は次のとおりとする。

1. 能力名
2. 現在値 `/` 潜在値
3. 能力上昇までの進捗バーと必要ポイント
4. `+1`、`+5`、`MAX` ボタン

行全体のクリックでは配分しない。誤タップとボタンの二重発火を防ぐため、配分操作はボタンだけに限定する。

### 3.3 ボタン仕様

| 操作 | 消費量 | 80到達時 | Undo単位 |
|---|---:|---|---|
| `+1` | 1ポイント | 必要量だけ消費 | 1回 |
| `+5` | 最大5ポイント | 80到達に必要な分だけ消費 | まとめて1回 |
| `MAX` | 残り全ポイント | 80到達に必要な分だけ消費し、余りは残す | まとめて1回 |

実消費量は次式で決める。

```text
actualSpend = min(requestedSpend, remainingPool, pointsRequiredToReach80)
```

`pointsRequiredToReach80` は現在値、繰越ポイント、通常コスト、潜在値超過後の倍率を使って算出する。`addAb()` に上限を超える値を直接渡してポイントを消失させてはならない。

### 3.4 無効状態

- 残りポイントが0なら全加算ボタンを無効化する。
- 対象能力が80なら、その行の全加算ボタンを無効化する。
- `+5` は残りが1～4でも有効とし、残り全部を使う。
- 履歴が0件なら Undo を無効化する。
- セッション開始後に変更がなければ「すべてリセット」を無効化する。

### 3.5 確定

- 残りポイントが0、または全能力が80のとき、現行どおり確定可能とする。
- 確定ボタンのタイミングと `allocDone()` の実行順を変えない。
- 配分ボタン、Undo、全リセットでは RNG を呼ばない。
- 確定後に既存仕様として行われる特性判定と RNG 消費は変更しない。

## 4. Undo・全リセットの状態設計

### 4.1 セッション開始スナップショット

`allocUI()` 開始時に、最低限次を複製して保持する。

```javascript
{
  abilities,
  carry,
  pool,
  diceIndex,
  touchedKeys
}
```

ゲーム全体の `S` を複製せず、配分処理が変更するフィールドだけを対象とする。

### 4.2 Undo履歴

1回のボタン操作につき1エントリを保存する。

```javascript
{
  abilityKey,
  spent,
  beforeAbility,
  beforeCarry,
  beforePool,
  beforeTouched
}
```

`+5` で実際に3ポイントだけ消費した場合も、3回ではなく1回の Undo で元に戻す。Undo 後は能力値、繰越、ポイント、進捗バー、総合値、`touchedKeys` を同時に再描画する。

### 4.3 すべてリセット

セッション開始スナップショットを復元し、Undo履歴を空にする。リセット自体を Undo 対象にはしない。誤操作防止の確認ダイアログは不要だが、ボタン名は「すべてリセット」とし、危険操作用の視覚スタイルを使用する。

## 5. レスポンシブ・アクセシビリティ

- 320px幅でも能力名、数値、3ボタンが重ならない。
- 狭い画面では情報部とボタン部を2段にする。
- 各ボタンのタップ領域は最低44×44px相当とする。
- ボタンに能力名を含む `aria-label` を付ける。例：`ミートに5ポイント配分`。
- 無効状態は色だけでなく `disabled` 属性で伝える。
- キーボードの Tab、Enter、Space で操作できる。
- 動作後にフォーカスを失わず、ライブ表示は `aria-live="polite"` で残りポイントを通知する。

## 9. 「失った特性」の定義

現行 `S.removed` は、以前保有していたが条件により失われた特性名の配列である。新規履歴データではない。

- 画面名は「失った特性」とする。
- 取得年、消失年、理由を保存していないため「特性履歴」とは呼ばない。
- 空の場合は「なし」ではなく「失った特性はありません。」とする。
- v1.6.0 では履歴スキーマを追加しない。

## 10. 契約画面と「年度schedule」

### 10.1 意味

`annualSchedule` は、複数年契約について各年度に支払われる基本年俸を並べた内部配列である。

```javascript
[
  { year: 2032, amount: 5060000, paid: true,  segmentId: "..." },
  { year: 2033, amount: 5060000, paid: false, segmentId: "..." }
]
```

これは試合日程や年間イベント予定ではない。したがって画面名を「年度別年俸」に変更する。

### 10.2 表示仕様

| 項目 | 表示例 |
|---|---|
| 現契約 | `2032～2033年　球団保有期間` |
| 契約残年数 | `1年` |
| 保証総額 | `1,012万円` |
| 年度別年俸 | `2032年 506万円（支払済み）` / `2033年 506万円` |

- 全年度を改行または行単位で表示する。
- `paid === true` は「支払済み」と表示する。
- 当年度、将来年度、支払済み年度を勝手に除外しない。
- 金額は既存の `fmtMoney()` と同じ丸め・桁区切りを使用する。
- `annualSchedule` が空の旧saveデータだけ `—` と表示する。

### 10.3 整合性検査

スクリーンショットでは `2032～2033年` に対して年度別表示が `2032年` だけに見えるため、次を自動テストする。

```text
annualSchedule.length == contract.years
startYear == annualSchedule[0].year
endYear == annualSchedule[last].year
guaranteedTotal == sum(annualSchedule.amount)
remainingYears == count(annualSchedule where paid == false)
remainingValue == sum(unpaid amount)
```

不一致がある場合は表示だけで補正せず、契約生成・正規化・支給済み更新のどこで欠落したかを特定する。

## 12. テスト仕様

### 12.1 能力配分

1. `+1` が現行1ポイント配分と一致する。
2. `+5` が5ポイントを1操作で消費する。
3. 残り3で `+5` を押すと3だけ消費する。
4. `MAX` が残り全量を使う。
5. 80到達に必要な量より残りが多い場合、余剰が残る。
6. 潜在値超過後も既存の3倍／4倍コストが維持される。
7. `+5` と `MAX` を Undo すると1回で完全復元する。
8. Undo 後に `touchedKeys` が操作前へ戻る。
9. 全リセットで能力、繰越、残り、総合、`touchedKeys` が開始時へ戻る。
10. Undo／リセット後の確定結果が、同じ最終配分を直接行った場合と一致する。
11. diceモードの割当順と結果が v1.5.2 と一致する。

### 12.2 RNG・固定seed

- 配分ボタン、Undo、リセットによる RNG 消費は0回。
- 確定時の既存 RNG 消費順を変更しない。
- 投手3seed、野手3seed以上で、同じ最終配分を与えた v1.5.2 と v1.6.0 の状態スナップショットを比較する。
- UI操作差以外の初期能力、イベント順、成績、昇降格、年俸、移籍、引退、殿堂判定に差がないこと。
