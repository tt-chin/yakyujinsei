## 1. 結論

v1.7.0 では次を実装する。

1. 4種類の画面テーマ
2. 3段階の文字サイズ
3. 標準／コンパクトの表示密度
4. ゲーム開始前とゲーム中の共通表示設定画面
5. `localStorage` による表示設定保存
6. テーマ切替に必要なCSS変数の整理
7. PC、スマートフォン、キーボード、アクセシビリティ対応

表示設定はゲームの見た目だけを変更する。能力、成績、イベント、選択肢、RNG、seed、URL、ゲーム状態には影響させない。

- CSSフレームワーク、npm依存、ビルドツールの追加

## 3. 現行構成と変更方針

### 3.1 現行確認結果

- `styles/base.css` に色、レイアウト、部品スタイルが混在している。
- `styles/jp-theme.css` が現在のライトレッド表示を上書きしている。
- 一部の色がCSS変数ではなく直接記述されている。
- `src/main.js` は `engine/game.js` だけを読み込む。
- 表示設定用の状態、UI、保存処理は存在しない。
- 引退画像の色は `game.js` の `imageColor` に固定されている。

### 3.2 基本方針

- 現在のライトレッド表示を既定テーマとして完全に維持する。
- テーマ差は原則CSSカスタムプロパティで表現する。
- JavaScriptはテーマID、文字サイズID、表示密度IDだけを管理する。
- `S` に表示設定を追加しない。
- 表示設定によって `board()`、イベント処理、RNG処理を再実行しない。
- 公開用 `yakyujinsei-site` は同期結果として扱い、開発元リポジトリで実装・テストしてから公開する。

## 4. 表示設定データモデル

### 4.1 保存キー

```javascript
const PREFERENCES_STORAGE_KEY = 'yakyujinsei.display.v1';
```

### 4.2 保存形式

```json
{
  "schemaVersion": 1,
  "theme": "standard",
  "fontSize": "medium",
  "density": "standard"
}
```

### 4.3 許可値

| 項目 | 許可値 | 既定値 |
|---|---|---|
| `theme` | `standard`, `night`, `classic`, `scoreboard` | `standard` |
| `fontSize` | `small`, `medium`, `large` | `medium` |
| `density` | `standard`, `compact` | `standard` |

### 4.4 読込時検証

- JSON解析に失敗した場合は既定値を使用する。
- `schemaVersion !== 1` は既定値へフォールバックする。
- 未知の値はその項目だけ既定値へ戻す。
- 読込失敗をゲーム開始エラーとして扱わない。
- `localStorage` が利用できない環境でも、現在のタブ内では設定変更を有効にする。
- 保存失敗時はゲームを停止せず、「この端末には設定を保存できませんでした。」と設定画面内だけに表示する。

### 4.5 ゲーム状態との分離

表示設定は次へ保存しない。

- 状態 `S`
- seed付きURL
- RNGスナップショット
- キャリア記録
- 引退リザルト

同じseed、同じ選択、異なるテーマでゲーム結果は完全に一致しなければならない。

### 5.3 追加セマンティック変数

色の直書きを減らすため、少なくとも次を追加する。

```css
--board-bg-start
--board-bg-end
--action-bg-start
--action-bg-end
--metric-bg
--bar-bg
--primary-button-start
--primary-button-end
--primary-button-text
--overlay-bg
--shadow-color
--focus-ring
--disabled-opacity
```

各部品はテーマ名ではなく意味に基づく変数を参照する。例えば `.btn.main` に `night` 固有色を直接書かない。

### 5.4 適用方法

`document.documentElement` に次を設定する。

```html
<html lang="ja" data-theme="standard" data-font-size="medium" data-density="standard">
```

CSS側は次の構造とする。

```css
:root,
:root[data-theme="standard"] { /* 現行色 */ }
:root[data-theme="night"] { /* ナイター色 */ }
:root[data-theme="classic"] { /* クラシック色 */ }
:root[data-theme="scoreboard"] { /* スコアボード色 */ }
```

bodyへ複数のテーマclassを付けない。切替時は`data-theme`を1つだけ更新する。

### 5.5 既定テーマの回帰条件

`standard` は v1.6.2 と次が同等であること。

- 背景色
- ボード色
- カード色
- ボタン色
- 成功／失敗／情報カード色
- サイコロ表示
- 入力欄
- 契約詳細ダイアログ
- ナビゲーションとタブ

CSS変数化に伴う1～2pxの内部差は許容するが、表示順、文章折返し、ボタン位置が不必要に変化してはならない。

## 6. 文字サイズ設定

### 6.1 選択肢

| ID | 表示名 | 倍率 |
|---|---|---:|
| `small` | 小さめ | 0.90 |
| `medium` | 標準 | 1.00 |
| `large` | 大きめ | 1.15 |

### 6.2 実装方法

```css
:root[data-font-size="small"]  { --font-scale: .90; }
:root[data-font-size="medium"] { --font-scale: 1; }
:root[data-font-size="large"]  { --font-scale: 1.15; }
```

主要なユーザー向け文字サイズは`rem`または`calc(<基準px> * var(--font-scale))`へ移行する。親子両方で倍率を掛けて二重拡大しない。

### 6.3 拡大対象

- カード見出し・本文
- 選択肢タイトル・補足
- ナビゲーション・タブ
- 能力名・能力値
- 成績表・契約表
- 入力ラベル
- ダイアログ本文
- 年度見出し

### 6.4 固定または別管理する対象

- アイコン画像そのもの
- 罫線幅
- Canvasの引退画像文字（v1.8.0まで変更しない）
- 最小44pxのタップ領域

`large`でも表を画面外へ押し出してページ全体を横スクロールさせない。表だけ必要に応じて内部横スクロールさせる。

## 7. コンパクト表示

### 7.1 名称

画面表示名は「コンパクト表示」とする。「簡潔表示」とは表記しない。

### 7.2 基本原則

コンパクト表示は情報量を削減せず、余白と部品間隔だけを縮める。

次は非表示にしてはならない。

- イベント選択肢
- 成功率、効果、リスク
- 契約年数、年俸、保証総額
- 能力現在値、潜在能力上限
- コンディション
- 年度成績
- 警告、エラー
- seed

### 7.3 変更値

| 部品 | 標準 | コンパクト |
|---|---:|---:|
| ログ左右padding | 14px | 9px |
| カードpadding | 12px 14px | 8px 10px |
| カード間gap | 10px | 6px |
| ボード上下padding | 現行値 | 約20%縮小 |
| ナビゲーションpadding | 現行値 | 約15%縮小 |
| 選択肢間隔 | 8px | 5px |
| パネル余白 | 現行値 | 約20%縮小 |

タップ領域の高さは最低44pxを維持する。文字サイズはコンパクト表示では変更せず、文字サイズ設定だけで決める。

### 7.4 適用方法

```css
:root[data-density="compact"] { --space-scale: .75; }
:root[data-density="standard"] { --space-scale: 1; }
```

可能な箇所は共通余白変数を使用する。既存画面ごとに重複したcompact用CSSを大量に追加しない。

## 8. 表示設定画面

### 8.1 導線

表示設定は次の2か所から開ける。

1. ゲーム開始画面：seed表示の下に「表示設定」ボタン
2. ゲーム中：上部ボード右端に歯車アイコンの「表示設定」ボタン

再スタートボタンと設定ボタンは別ボタンとし、誤タップしない間隔を確保する。

### 8.2 ダイアログ構成

```text
表示設定

テーマ
○ スタンダード  ○ ナイター
○ クラシック    ○ スコアボード

文字サイズ
○ 小さめ  ○ 標準  ○ 大きめ

表示密度
○ 標準  ○ コンパクト

[初期設定に戻す] [閉じる]
```

### 8.3 操作仕様

- 選択した時点で画面へ即時反映し、保存する。
- 「閉じる」は現在の設定を維持して閉じる。
- 「初期設定に戻す」は`standard / medium / standard`へ戻す。
- 初期設定への復帰前に確認ダイアログは表示しない。
- ゲーム開始前に設定しても入力中の選手名、ポジション、seedを失わない。
- ゲーム中に設定しても現在のタブ、スクロール位置、選択肢、配分途中状態を失わない。

### 8.4 アクセシビリティ

- `role="dialog"`、`aria-modal="true"`、見出しとの関連付けを行う。
- 開いたとき見出しまたは最初の設定へフォーカスを移す。
- Tabフォーカスをダイアログ内に閉じ込める。
- Escapeで閉じる。
- 閉じた後は開いたボタンへフォーカスを戻す。
- テーマ選択は色見本だけでなく名称を表示する。
- 現在選択中の値を`checked`または`aria-checked`で伝える。
- フォーカスリングを全テーマで見える色にする。

## 9. 起動・適用順序

1. `main.js`から表示設定モジュールを先に読み込む。
2. `localStorage`を安全に読み取る。
3. 値を検証する。
4. `document.documentElement.dataset`へ適用する。
5. 設定UIを初期化する。
6. 既存の`engine/game.js`を起動する。

推奨`main.js`：

```javascript
import { initializeDisplayPreferences } from './ui/preferences.js';

initializeDisplayPreferences();
await import('./engine/game.js');
```

ゲームエンジンの読込順変更によってRNG初期化やURL処理が変わらないことをテストする。トップレベル`await`を避ける必要がある場合は、設定値の読込・dataset適用だけを副作用のない先行モジュールとして実行してから`game.js`を読み込む。

## 10. モジュール構成

### 10.1 作成予定

```text
src/
  ui/
    preferences.js
    preferences-dialog.js

styles/
  themes.css
  preferences.css
```

既存構成に合わせ、`preferences.js`とダイアログ描画を分ける必要がない規模なら1ファイルへ統合してよい。空モジュールは作らない。

### 10.2 責務

| モジュール | 責務 |
|---|---|
| `preferences.js` | 既定値、検証、読込、保存、dataset適用、変更通知 |
| `preferences-dialog.js` | ダイアログ生成、操作、フォーカス管理 |
| `themes.css` | 4テーマのCSS変数 |
| `preferences.css` | 設定画面、文字倍率、表示密度 |

### 10.3 禁止依存

- `preferences.js` から `engine/game.js` をimportしない。
- `preferences.js` から状態`S`、`R()`、ゲーム関数を参照しない。
- `game.js` から設定ダイアログのDOM内部構造を操作しない。
- テーマ切替イベントで`board()`や画面モデル生成関数を呼ばない。

## 11. 1.8.0への互換性

v1.8.0では引退リザルト画像をテーマ連動させる予定だが、v1.7.0ではCanvasの`imageColor`を変更しない。

v1.7.0で確定する互換インターフェースはテーマIDだけとする。

```javascript
getDisplayPreferences().theme
// standard | night | classic | scoreboard
```

v1.8.0はこのIDをCanvas用色へ変換する。CSSの計算済み色を直接Canvasへコピーする方式には依存しない。共有画像生成時にDOMテーマとゲームロジックを結合しない。

## 12. RNG・seed・ゲーム仕様保護

### 12.1 RNG

次の操作によるRNG消費は必ず0回とする。

- 設定画面を開く／閉じる
- テーマを切り替える
- 文字サイズを切り替える
- コンパクト表示を切り替える
- 初期設定に戻す
- 保存設定を読み込む

### 12.2 seed-only URL

- 表示設定をURLへ追加しない。
- `theme`、`fontSize`、`density`のクエリパラメータを新設しない。
- 共有URLは従来どおり`?seed=<SEED>`だけを使用する。
- 同じseedでやり直しても端末の表示設定は維持する。
- 新しい野球人生を始めても表示設定は維持する。

### 12.3 DOMと処理順

- ゲームカード、選択肢、タブの論理的なDOM順を変更しない。
- CSSの見た目上の並べ替えを行わない。
- フォント変更による高さの変化を、イベント処理の条件に利用しない。
- `ResizeObserver`は表示調整だけに使用し、ゲーム状態を変更しない。

## 13. CSS移行規則

1. `jp-theme.css`の現行ライトレッド値を`standard`テーマへ移す。
2. `base.css`に残る暗色の旧既定値とテーマ上書きの二重構造を整理する。
3. 色の意味が同じ直書きはセマンティック変数へ置換する。
4. 球団固有色など、ゲームデータとして必要な動的色は維持する。
5. 成功、警告、情報の意味をテーマごとに逆転させない。
6. `prefers-reduced-motion`対応を維持する。
7. 既存の560px最大幅とsticky board／action領域を維持する。

`jp-theme.css`は互換用に残してもよいが、テーマ定義と重複させない。不要になった場合はHTML参照と同じ変更で安全に削除する。

## 14. テスト仕様

### 14.1 設定単体テスト

1. 保存値なしで既定値になる。
2. 4テーマすべてを保存・再読込できる。
3. 3文字サイズすべてを保存・再読込できる。
4. 2表示密度を保存・再読込できる。
5. 壊れたJSONで起動できる。
6. 未知のテーマIDだけ既定値へ戻る。
7. `localStorage.setItem()`失敗でもゲームが動く。
8. 初期設定へ正しく戻る。

### 14.2 組合せテスト

最低限、次の24組合せを確認する。

```text
4テーマ × 3文字サイズ × 2表示密度 = 24組合せ
```

自動スクリーンショット比較では代表6組合せ以上、手動確認では全24組合せを対象とする。

- 上部ボード
- ホームのイベントカード
- 選択肢
- サイコロトレーニング
- 能力ポイント配分
- 選手／能力・コンディション
- 選手／特性

### 14.4 ビューポート

- 320×568

- 430×932

- 文字切れがない

- 引退年、最終成績、殿堂判定
- RNG消費回数
