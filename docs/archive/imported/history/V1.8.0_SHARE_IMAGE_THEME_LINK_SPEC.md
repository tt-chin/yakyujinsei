## 1. 実装範囲

### 1.1 必須機能

1. 引退リザルト画像へ現在選択中の画面テーマを適用する。
2. `standard`、`night`、`classic`、`scoreboard`の4種類に対応する。
3. 画像プレビュー、端末ダウンロード、Web Shareで同じ画像データを使用する。
4. テーマ変更後、引退結果画面を表示中なら画像を再生成する。
5. 不明なテーマ、設定読込失敗、1.7.0設定API不在時は`standard`へフォールバックする。
6. 画像内の本文、表、罫線、特性タグ、成功／警告色の視認性を全テーマで確保する。

### 1.2 対象外

- 画像の掲載項目追加・削除
- 画像サイズ、表の列、統計計算、年度履歴の変更
- 画像レイアウトの全面再設計
- 文字サイズ設定を画像へ反映すること
- コンパクト表示を画像へ反映すること
- JPG、PDF、SVG形式の追加
- SNS別テンプレートや縦長／正方形画像の追加
- サーバー側画像生成
- ゲーム進行の永久保存
- seed、RNG、能力、成績、表彰、殿堂判定の変更

## 2. 現行画像生成の確認結果

現行版は`game.js`内でCanvasを生成し、次の処理を行っている。

- 論理幅：920px
- 出力倍率：2倍
- 高さ：成績・表彰・年度履歴件数から動的計算
- 背景・文字・罫線・タグ色：`imageColor`および`tagColor()`内へ固定記述
- 出力：`canvas.toDataURL('image/png')`
- プレビュー：生成したData URLを`img`へ設定
- 共有：Data URLからBlobとFileを生成してWeb Share
- 非対応時：PNGとしてダウンロード
- ファイル名：`野球人生リザルト_<選手名>.png`

現在は画面テーマとCanvas色が分離されており、画面の色を変更しても画像は常にライトレッド系になる。

## 4. 設計原則

1. CanvasはCSS変数やDOMの計算済み色を直接読み取らない。
2. 画像専用の固定色盤をJavaScriptで管理する。
3. 画面テーマIDだけを入力し、画像色盤へ変換する。
4. 1回の生成では1テーマ分だけを描画する。
5. プレビューと保存用画像を別々に生成しない。
6. テーマ変更でゲーム画面モデルやRNG処理を再実行しない。
7. 色以外のCanvas描画順、座標、統計値を維持する。

CSS色をCanvasへ直接転写しない理由：

- CanvasではCSSの透明度やgradientをそのまま利用できない。
- テーマCSSの小変更で画像スナップショットが予期せず変わる。
- ダークテーマの画面色を印刷・共有画像へそのまま使うと可読性が下がる可能性がある。
- 画像用色盤を固定すると各テーマの再現性とテストが安定する。

## 5. モジュール設計

### 5.1 新規ファイル

推奨構成：

```text
src/
  ui/
    share-theme.js
```

現行画像生成処理を別モジュールへ安全に移せる場合のみ、次を追加してよい。

```text
src/
  ui/
    share-image.js
    share-theme.js
```

ただし、1.8.0の目的はテーマ連動であり、大規模な画像生成リファクタリングを必須にしない。関数移動によってレイアウトや生成結果が変わる場合は、`game.js`に描画処理を残し、色盤だけを分離する。

### 5.2 `share-theme.js`の責務

- 4テーマの画像色盤を所有する。
- テーマIDを検証する。
- 不明なIDを`standard`へフォールバックする。
- 呼出側に変更不能な色盤を返す。
- ゲーム状態、DOM、`localStorage`、RNGへ依存しない。

### 5.3 公開関数

```javascript
export function getSharePalette(themeId) {
  return SHARE_PALETTES[themeId] || SHARE_PALETTES.standard;
}
```

戻り値を描画中に書き換えない。必要に応じて`Object.freeze()`を使用する。

### 7.2 タグ色の方針

| 種類 | 適用対象 | 表現 |
|---|---|---|
| normal | 通常の保有特性 | テーマのaccent系 |
| removed | 失った特性 | 低彩度＋取消線 |
| gold | 歴史的選手、Team Taiwan等 | 金色系 |
| yellow | ゴールデングラブ系 | 黄色系 |
| silver | 天才 | 銀色系 |
| negative | マイナス特性 | 赤色系 |
| team | ミスター・チーム | 球団色を境界・文字へ使用 |

タグ背景と文字は各テーマで4.5:1以上を目標とする。球団色が背景に対して読みにくい場合は、文字をテーマ本文色へ戻し、球団色は境界線だけに使用する。

### 7.3 `night`タグ補足

ダーク背景でタグまで暗くすると判読しにくいため、タグは背景より一段明るいパネル色を使用する。黄色・金色タグは明るい背景に暗い文字を使用し、白文字を重ねない。

### 7.4 `scoreboard`タグ補足

スコアボードテーマでは黄色が通常accentになるため、金・黄色タグと通常タグが同一に見えないようにする。

- 通常タグ：緑＋淡い生成り
- 金タグ：濃い金＋生成り
- 黄色タグ：明るい黄＋濃い茶
- マイナスタグ：赤

## 8. 画像生成データフロー

```text
表示設定
  ↓ theme IDのみ取得
getSharePalette(themeId)
  ↓ 画像専用色盤
既存Canvas描画
  ↓ 1つのPNGデータ
プレビュー／Web Share／ダウンロード
```

### 8.1 生成時テーマ取得

引退リザルト画像を生成する直前にテーマを取得する。

```javascript
const themeId = getDisplayPreferences?.().theme || 'standard';
const palette = getSharePalette(themeId);
```

ゲーム開始時のテーマを固定保存しない。画像生成時点で画面に適用されているテーマを使用する。

### 8.2 フォント読込

可能な場合は描画前に次を待つ。

```javascript
await document.fonts?.ready;
```

`document.fonts`非対応または読込失敗時は既存フォールバックフォントで生成する。フォント読込失敗を画像生成失敗にしない。

### 8.3 同一画像の利用

1回生成したPNGを次の3用途で共用する。

- 画面プレビュー
- Web Share API
- `<a download>`

共有時にもう一度Canvasを描画してはならない。プレビューと保存画像のテーマや内容がずれるためである。

## 9. テーマ変更時の再生成

### 9.1 基本動作

引退結果画面が表示されている状態でテーマを変更した場合、設定変更イベントを受けて画像を再生成する。

### 9.2 再生成条件

次をすべて満たす場合だけ再生成する。

- 変更項目に`theme`が含まれる。
- 引退リザルトのプレビュー要素がDOM上に存在する。
- 前回生成テーマと新テーマが異なる。
- 現在画像生成中ではない。

文字サイズまたは表示密度だけの変更では画像を再生成しない。

### 9.3 連続変更対策

- テーマを素早く連続変更した場合は最後の値だけを反映する。
- 100～200ms程度のdebounceを使用してよい。
- 古い非同期生成結果が新しい結果を上書きしないようgeneration tokenを使用する。
- 再生成中も既存画像を表示し、空白にしない。
- 失敗時は既存画像を維持し、`standard`で1回だけ再試行する。

### 9.4 イベント解除

引退結果画面を破棄または新しいゲームを開始するとき、画像専用listenerを解除する。重複listenerによる複数生成を防止する。

## 10. Canvas描画置換仕様

### 10.1 置換対象

現行の次の固定色をpalette参照へ変更する。

- Canvas全面背景
- 外枠
- ヘッダー補助文字
- 選手名
- 本文
- セクション見出し
- 表見出し
- 表本文
- 区切り線
- 通算収入
- seed・バージョン
- 特性タグの背景、境界、文字、取消線
- 故障年度・警告文字

### 10.2 維持対象

- Canvas幅、高さ計算、scale
- 全てのx／y座標
- 表列幅
- 年度履歴の省略処理
- テキスト内容
- 数値形式
- 表彰の2列配置
- 特性タグの分類条件
- ファイル名

### 10.3 球団色

`ミスター・チーム`タグで使用している球団色は維持する。ただし可読性を保証する。

推奨処理：

1. 球団色をタグborderへ使用する。
2. 球団色とタグ背景のコントラストを計算する。
3. 文字コントラストが4.5:1未満なら、文字はpaletteの`text`へ戻す。
4. 色解析に失敗した場合はpaletteの`accent`を使用する。

球団データやチーム判定ロジックは変更しない。

## 11. UI仕様

### 11.1 プレビュー

- 現行どおり画像をページ幅に合わせて表示する。
- 画像の周囲に現在テーマと調和する境界を付けてよい。
- 画像内へテーマ名を追加しない。
- 代替テキストは「引退リザルト画像」を維持する。

### 11.2 操作ボタン

次を維持する。

- `保存／画像を共有`
- `端末へダウンロード`

テーマ別のボタン名称変更やSNS専用ボタン追加は行わない。

### 11.3 再生成中

再生成が200msを超える場合のみ、プレビュー付近へ「画像を更新中…」を表示してよい。ボタン連打による旧画像共有を防ぐため、生成中は共有／ダウンロードを一時的にdisabledにする。

生成完了後は新しいPNGをボタンに接続してからdisabledを解除する。

## 12. 保存・共有仕様

### 12.1 ファイル名

```text
野球人生リザルト_<選手名>.png
```

テーマ名をファイル名へ追加しない。

### 12.2 Web Share

- `navigator.canShare({ files })`の既存判定を維持する。
- Share Sheetのtitle、textを変更しない。
- ユーザーキャンセル`AbortError`ではダウンロードへフォールバックしない。
- Web Share非対応時はダウンロードへフォールバックする。

### 12.3 ダウンロード

- PNG形式を維持する。
- 透明背景にせず、paletteの`background`で全面を塗る。
- iOS長押し保存の案内を維持する。
- プレビューに表示された画像と保存ファイルのバイト内容が同じであることを確認する。

## 13. RNG・ゲーム仕様の保護

次の処理でRNGを呼ばない。

- テーマID取得
- 色盤取得
- Canvas生成
- テーマ変更による再生成
- ダウンロード
- Web Share
- 画像生成失敗時のフォールバック

画像生成前後で次が変化してはならない。

- `S`
- RNG内部状態
- RNG消費回数
- seed
- 成績
- 表彰
- 特性
- 殿堂判定
- キャリア収入
- 引退理由

画像生成関数へゲーム状態を渡す場合は読み取り専用スナップショットとし、描画処理から状態を書き換えない。

## 14. seed-only・プライバシー

- テーマをURLへ保存しない。
- 共有URLは`?seed=<SEED>`だけを維持する。
- PNGにリポジトリURL、GitHub情報、内部パスを追加しない。
- PNGへ`localStorage`内容を埋め込まない。
- 現行どおり画像内にseedを表示してよい。
- 選手名以外のユーザー入力を新たに画像へ追加しない。

## 15. エラー処理

| 状況 | 動作 |
|---|---|
| 不明なtheme ID | `standard`を使用 |
| 設定APIが未定義 | `standard`を使用 |
| 色盤キー不足 | `standard`の同一キーを補完 |
| `document.fonts`失敗 | フォールバックフォントで続行 |
| Canvas context取得失敗 | エラー表示、共有ボタン無効 |
| `toDataURL`失敗 | エラー表示、再試行導線 |
| 再生成失敗 | 旧画像維持＋standardで1回再試行 |
| Web Share失敗 | AbortError以外はダウンロードへ切替 |

エラー処理でRNGやゲーム進行を再実行しない。

## 16. テスト仕様

### 16.1 色盤単体テスト

1. 4つのtheme IDが対応色盤を返す。
2. 不明ID、空文字、null、undefinedがstandardを返す。
3. 全色盤が必須キーを持つ。
4. 色値が有効なCSSカラー形式である。
5. 色盤が呼出側から変更されない。

### 16.2 画像生成テスト

各テーマで同じ固定状態からPNGを生成し、次を比較する。

- 幅が一致
- 高さが一致
- テキスト内容が一致
- 表の列数・行数が一致
- 色だけがテーマ別に変わる
- 背景が透明でない
- seedとバージョンが表示される
- 日本語が文字化けしない

### 16.3 画像スナップショット

最低限、次の4状態×4テーマを確認する。

| 状態 | 確認目的 |
|---|---|
| 投手・短期キャリア | 投手表、国際成績なし |
| 投手・長期キャリア | 多年度、長い表彰、国際成績 |
| 野手・短期キャリア | 野手列、少数特性 |
| 野手・長期キャリア | 長い球団名、多数特性、多リーグ |

合計16画像を自動または半自動で比較する。

### 16.4 タグテスト

各テーマで次を含む状態を確認する。

- 通常特性
- 失った特性＋取消線
- 天才
- 歴史的選手
- ゴールデングラブ系
- マイナス特性
- ミスター・チーム＋明るい球団色
- ミスター・チーム＋暗い球団色

### 16.5 再生成テスト

1. 引退結果表示中にstandard→nightへ変更すると画像が変わる。
2. fontSizeだけ変更しても画像再生成回数は増えない。
3. densityだけ変更しても画像再生成回数は増えない。
4. themeを連続変更して最後のテーマが表示される。
5. 古い生成結果が新しい結果を上書きしない。
6. 再生成後の共有・ダウンロードが新しい画像を使用する。
7. 新しいゲーム開始後に旧listenerが残らない。

### 16.6 共有・保存テスト

- iOS Safari：Web Share、キャンセル、長押し保存
- Android Chrome：Web Share、ダウンロード
- Windows Chrome：ダウンロード
- Windows Edge：ダウンロード
- `navigator.canShare`非対応環境：フォールバック

### 16.7 コントラストテスト

- 通常文字と背景：4.5:1以上
- 大きな見出し：3:1以上
- 表罫線・タグ境界：3:1以上を目標
- マイナス年度が色だけでなく内容でも識別可能
- 失った特性が色と取消線の両方で識別可能

### 16.8 RNG・固定seed回帰

投手3seed、野手3seed以上で、画像生成前後の重要状態JSONとRNGカウンタを比較する。

```text
画像生成によるRNG消費 = 0
テーマ変更によるRNG消費 = 0
画像再生成によるRNG消費 = 0
```

4テーマでゲームの最終成績、表彰、引退年、殿堂判定が一致すること。

### 16.9 静的検証

- JS構文正常
- import/export正常
- 404なし
- 画像色の固定値が旧`imageColor`へ残っていない
- Canvas描画コードにtheme別条件が散在していない
- `localStorage`を画像モジュールが直接参照していない
- `&theme=`等のURLパラメータがない
- GitHub固定URLを追加していない
