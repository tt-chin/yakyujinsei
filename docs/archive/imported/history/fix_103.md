# v1.0.3 修正指示書

## 1. 対象

- 開発リポジトリ: `tt-chin/yakyujinsei`（Private）
- 対象ブランチ: `main`
- 現行バージョン: `1.0.2`
- 修正後バージョン: `1.0.3`
- 主な対象ファイル:
  - `docs/src/engine/game.js`
  - `docs/src/engine/salary-promotion-policy.js`（共通計算を切り出す場合）
  - `docs/src/config.js`
  - 関連テストファイル
- 公開用リポジトリ `tt-chin/yakyujinsei-site` は直接編集しないこと。
- 開発リポジトリの `main/docs/**` を更新・pushし、既存の `Publish website` Workflowで公開用リポジトリへ同期すること。

## 2. 目的

次の4分類を修正する。

1. 海外球団在籍中に表示されるNPB復帰オファーで、契約年数・年俸・契約総額・現年俸との差が表示されず、選択前に契約条件を比較できない問題。
2. FA市場の移籍先オファーが現年俸より低くなる問題、および画面の提示額と実際の契約年俸が異なり得る問題。
3. 表示上は好成績でも、年俸が実成績ではなく隠れた能力評価 `d` だけで決まり、複数年契約中にも毎年再計算される問題。
4. 捕手・内野手・外野手の総合能力にスタミナが直接反映されない問題。

NPB復帰では海外年俸より低い提示を許容する。一方、FAによる獲得オファーには、国内FA・海外FAそれぞれの最低昇給率を適用する。

投手の総合能力計算式は変更しないこと。

## 3. 不具合1: NPB復帰オファーの契約条件表示

### 3.1 現在の問題

海外組織（KBO・CPBL・MiLB・MLB）在籍中にNPB復帰オファーが発生した場合、現在の選択肢はおおむね次の情報しか表示しない。

```text
NPBへ復帰：千葉オーシャンズ
NPB一軍契約
```

実際には選択後、`signTo()` 内でNPB基準の年俸と1～3年の契約年数が決定される。しかし、選択前には次の情報が分からない。

- 契約年数
- 年俸
- 契約総額
- 現年俸との差額・増減率

そのため、海外球団への残留とNPB復帰を合理的に比較できない。

### 3.2 現行のNPB復帰年俸計算

NPB復帰後の年俸は海外での現年俸を引き継がず、NPBの所属レベル基準で再計算される。

復帰先レベルは現行どおり次の条件とする。

```javascript
const lv = o >= 53 ? 'NPB1' : 'NPB2';
```

年俸評価値は次の意味で計算する。

```text
p = floor（本季成績評価 d + 当年度タイトル加点）
p は 0～26 に制限
```

当年度タイトル加点は現行の `salaryAwardBonus()` を使用し、上限3を維持する。

NPB一軍の基準年俸は現行どおり次の式を使用する。

```text
1,600万円
＋ p × 400万円
＋ max(0, p - 7)² × 300万円
```

`salaryFor('NPB1', p)` の最低・最高、守備位置係数 `dpMult()` および1万円単位の丸め方は現行仕様を維持する。

NPB復帰オファーには海外移籍・FA用の割増を付けず、契約倍率は現行どおり `1.00` とする。

```text
NPB復帰年俸
= salaryFor(lv, salaryEvaluationD(lastD, honors, year))
  × 1.00
  × dpMult()
```

### 3.3 修正内容

オファー表示前に、次の情報を一度だけ生成してofferオブジェクトへ保存すること。

```javascript
{
  org: 'NPB',
  teamId,
  level,
  years,
  annualSalary,
  totalValue,
  currentSalaryDifference,
  currentSalaryDifferenceRate,
  multiplier: 1.00,
  contractType: 'RETURN_TO_NPB'
}
```

契約年数は現行範囲の1～3年を維持する。ただし、選択肢を描画する前に一度だけ抽選し、選択後に再抽選してはならない。

表示例:

```text
NPBへ復帰：千葉オーシャンズ
NPB一軍｜年俸2億6,800万円｜2年契約｜総額5億3,600万円
現年俸比 −2,000万円（−6.9%）
```

表示要件:

- 年俸は `annualSalary` を表示する。
- 契約年数は `years` を表示する。
- 契約総額は `annualSalary × years` を表示する。
- 現年俸との差額は `annualSalary - S.currentSalary` を表示する。
- 現年俸との差額が正の場合は `＋`、負の場合は `−`、同額の場合は `±0` を表示する。
- 増減率は現年俸を基準に小数第1位まで表示する。現年俸が0の場合は増減率を表示しない。
- 金額は既存の日本円表示関数を使用し、単位や桁区切りを独自実装で重複させない。
- 実際の契約には、画面に表示した同じofferオブジェクトの `years` と `annualSalary` を使用する。

### 3.4 NPB復帰時の減俸は許容する

NPB復帰はFAによる純粋な挖角とは別扱いとし、現年俸以上を保証しない。

海外リーグとNPBでは年俸基準が異なるため、次の状態を正常仕様として許容する。

```text
海外での現年俸 > NPB復帰提示年俸
```

ただし、減俸額と減俸率を選択前に必ず表示し、プレイヤーが残留と比較できるようにすること。

NPB復帰年俸へ、後述する国内FA `+5%` または海外FA `+10%` の最低保証を適用してはならない。

## 4. 不具合2: FAオファーの年俸と表示・契約不一致

### 4.1 現在の問題

現在のFA市場では、移籍先の提示年俸がおおむね次の式で新規計算される。

```text
目的リーグの年俸基準 × FA倍率
```

現年俸を最低基準としていないため、本季成績が低下した場合や、現契約が過去の高評価・高倍率で締結されている場合、挖角球団の提示年俸が現年俸を下回る。

また、現在の画面表示はおおむね次を使用する。

```javascript
salaryFor(x.lv, d) * x.mult
```

一方、実際の `signTo()` は次の要素も含む `salaryCandidate()` を使用する。

- 当年度タイトル加点
- 守備位置係数
- 1万円単位の丸め

このため、画面の提示年俸と実際の契約年俸が異なり得る。

契約年数も選択後に1～4年で抽選されるため、選択前に契約総額を比較できない。

### 4.2 FA最低提示年俸

FAによる獲得オファーには、次の最低昇給率を適用する。

| FA種別 | 最低提示年俸 |
| --- | ---: |
| 国内FA | 現年俸の105%以上 |
| 海外FA | 現年俸の110%以上 |

1万円未満の端数は切り上げ、最低率を下回らないようにする。

```javascript
const domesticFloor = Math.ceil(S.currentSalary * 1.05 / 10000) * 10000;
const overseasFloor = Math.ceil(S.currentSalary * 1.10 / 10000) * 10000;
```

FA提示年俸は次の意味になるよう計算する。

```text
baseOffer
= salaryFor(
     destinationLevel,
     salaryEvaluationD(lastD, honors, year)
   )
   × faMultiplier
   × dpMult()

国内FA提示年俸
= max（baseOffer, domesticFloor）

海外FA提示年俸
= max（baseOffer, overseasFloor）
```

FA倍率は現行どおり維持する。

| 移籍種別 | 現行倍率 |
| --- | ---: |
| NPB国内FA | 1.25 |
| 海外FAのKBO・CPBL・MLB | 1.30 |

目的リーグの現行最高年俸と既存倍率・守備位置係数を適用しても最低提示年俸を満たせない設計上の上限がある場合、その球団・リーグのオファーは生成しないこと。上限を無視して無制限に年俸を引き上げてはならない。

### 4.3 FAオファーを選択前に確定する

各FAオファーについて、画面表示前に次を一度だけ生成すること。

```javascript
{
  org,
  teamId,
  level,
  years,
  annualSalary,
  totalValue,
  currentSalaryDifference,
  currentSalaryDifferenceRate,
  multiplier,
  contractType
}
```

契約年数は現行範囲の1～4年を維持する。チーム・年数・年俸は選択肢表示前に確定し、ボタン押下時に再抽選・再計算してはならない。

表示例:

```text
東京グランズ（NPB一軍）
年俸3億240万円｜3年契約｜総額9億720万円
現年俸比 ＋1,440万円（＋5.0%）
```

表示した `annualSalary`、`years`、`totalValue` と、契約後の `S.currentSalary`、`S.ct.annualSalary`、`S.ct.yrs`、`S.ct.totalValue` は完全に一致しなければならない。

同じオファーの情報を、表示用と契約用で別々に計算してはならない。

### 4.4 宣言残留

FA宣言後の `宣言残留` は現行仕様を維持する。

- 現球団との契約更新で現年俸を下回らない。
- 現行の残留倍率を変更しない。
- 国内FA・海外FAの移籍先最低昇給率を宣言残留へ重複適用しない。

### 4.5 球団別の追加倍率は導入しない

今回、球団資金力・人気・順位などによる新しい球団別年俸倍率は導入しない。

同一リーグ・同一レベル・同一契約条件の球団が同額を提示する現行設計は、今回の修正対象外とする。

## 5. 不具合3: 実成績と複数年契約を無視した年俸更新

### 5.1 現在の問題

現在のプロ野手のシーズン評価 `S.lastD` は、表示された実成績ではなく能力値から次のように計算される。

```text
d
= ミート × 50%
 + パワー × 20%
 + 選球眼 × 18%
 + 走力 × 12%
 - 所属レベル基準
 - 0.5
```

この `d` は成績シミュレーションの基礎値としては使用できるが、現在の年俸計算では実際に記録した次の成績を直接評価しない。

- 出場・打席
- 打率・出塁率・長打率・OPS
- 安打・本塁打・打点・盗塁
- 守備貢献
- 投手の防御率・WHIP・投球回・勝利・セーブ・ホールド・奪三振

そのため、実際にはNPB一軍でレギュラー水準以上の成績を残していても、能力由来の `d` が0以下ならNPB一軍最低年俸まで下がり得る。

一方、降格・戦力外判定では `goodReal` により実成績を評価している。現在は次の矛盾がある。

```text
実成績が良い
→ 降格は保護される
→ しかし年俸は最低額まで下がり得る
```

また、`phaseEnd()` は契約残年数にかかわらず毎年 `pendingOffseasonSalary` を作り、次年度開始前に年俸を再計算する。`S.ct.annualSalary` と `S.ct.totalValue` を持つ複数年契約であっても、契約途中に年俸が変わり得る。

これは固定年俸の複数年契約として不整合である。

### 5.2 修正方針

年俸計算は次の二層構造にする。

```text
能力由来評価
＋実成績による最低評価保証
＋当年度タイトル加点
```

実装上は、現在の能力由来 `lastD` と、後述する実成績評価下限 `performanceFloorD` の高い方を採用する。

```javascript
const salaryBaseD = Math.max(
  Number(S.lastD) || 0,
  performanceFloorD(S.lastSt, S.lv, S.pos, S.role)
);

const salaryD = salaryBaseD + salaryAwardBonus(S.honors, S.year);
```

`salaryAwardBonus()` の現行加点と上限3は変更しない。

この変更は年俸評価専用とする。シーズン成績生成、昇降格、海外移籍資格などで使用する現行 `S.lastD` 自体を書き換えてはならない。

### 5.3 野手の実成績評価下限

野手は規定打席に近いレギュラーを基本とし、まずOPSによる最低評価を決める。

OPSは既存表示と同じ方法で算出する。

```text
OPS = 出塁率 + 長打率
```

`PA >= 350` の場合、該当する最も高い値を `performanceFloorD` とする。

| 実成績 | 最低評価 `performanceFloorD` |
| --- | ---: |
| OPS `.900` 以上 | 12 |
| OPS `.850` 以上 | 9 |
| OPS `.800` 以上 | 6 |
| OPS `.750` 以上 | 3 |
| OPS `.720` 以上 | 1 |
| OPS `.720` 未満 | 0 |

規定打席未満またはOPSだけでは評価が低い場合も、次の実績による最低評価を適用する。複数条件に一致した場合は最大値だけを採用し、加算しない。

| 実績 | 最低評価 `performanceFloorD` |
| --- | ---: |
| 30本塁打以上、100打点以上、または40盗塁以上 | 6 |
| 20本塁打以上、70打点以上、または25盗塁以上 | 3 |
| 12本塁打以上、55打点以上、または15盗塁以上 | 1 |

守備貢献は次の最低評価を追加する。打撃評価と加算せず、最大値を採用する。

| 守備貢献 `DEF` | 最低評価 `performanceFloorD` |
| --- | ---: |
| `+10` 以上 | 3 |
| `+5` 以上 | 1 |
| `+5` 未満 | 0 |

最終的な野手の実成績評価下限は次の最大値とする。

```text
max（OPS評価、長打・打点・盗塁評価、守備評価）
```

マイナス守備貢献を理由に評価下限を負数へ下げてはならない。守備位置の契約価値は既存の `dpMult()` で別途反映する。

### 5.4 投手の実成績評価下限

投手は先発と中継ぎ・抑えで分ける。

先発投手は `IP >= 100` の場合、防御率またはWHIPのうち該当する最も高い最低評価を採用する。

| 先発実績 | 最低評価 `performanceFloorD` |
| --- | ---: |
| ERA `2.00` 以下、またはWHIP `1.00` 以下 | 12 |
| ERA `2.75` 以下、またはWHIP `1.10` 以下 | 9 |
| ERA `3.50` 以下、またはWHIP `1.25` 以下 | 6 |
| ERA `4.20` 以下、またはWHIP `1.35` 以下 | 3 |
| 上記未満 | 0 |

中継ぎ・抑えは `G >= 35` の場合、防御率・WHIP・セーブ・ホールドのうち該当する最も高い最低評価を採用する。

| 中継ぎ・抑え実績 | 最低評価 `performanceFloorD` |
| --- | ---: |
| ERA `1.80` 以下、WHIP `0.95` 以下、40セーブ以上、または40ホールド以上 | 12 |
| ERA `2.50` 以下、WHIP `1.10` 以下、35セーブ以上、または35ホールド以上 | 9 |
| ERA `3.20` 以下、WHIP `1.25` 以下、25セーブ以上、または25ホールド以上 | 6 |
| ERA `4.20` 以下、WHIP `1.35` 以下、15セーブ以上、または15ホールド以上 | 3 |
| 上記未満 | 0 |

勝利数・奪三振は既存タイトル加点と重複しやすいため、今回の最低評価表には追加しない。

### 5.5 複数年契約中の年俸固定

複数年契約が残っている間は、次を固定する。

```text
S.currentSalary = S.ct.annualSalary
S.ct.totalValue = S.ct.annualSalary × 契約年数
```

シーズン終了ごとに `pendingOffseasonSalary` を作成して年俸を再計算してはならない。

年俸を再計算できるのは次の場合だけとする。

- 契約満了後の契約更新
- 球団保有権による新契約
- 契約延長に合意した時
- 国内FA・海外FAで新球団と契約した時
- 海外移籍またはNPB復帰で新球団と契約した時
- 戦力外後に新球団と契約した時
- 昇格・降格により所属レベル基準が変わり、現行仕様上、新年俸を決定する時

次の場合は年俸を再計算しない。

- 同じ複数年契約の2年目以降へ進むだけの場合
- 契約期間中に好成績・不振・タイトル獲得が発生しただけの場合
- 同一組織内の通常シーズン継続で、新契約も昇降格もない場合

当年度の好成績・タイトルは契約途中の固定年俸を変更せず、次の新契約時の評価に使用する。

### 5.6 単年契約・契約更新時の減俸

単年契約満了後または新契約締結時は、実成績評価下限を含む新しい `salaryD` で年俸を計算してよい。

ただし、既存の次の保護は維持する。

- 球団保有権による更新時の年俸不減。
- 宣言残留時の年俸不減。
- 昇格時の年俸不減。
- 当年度の主要タイトルによる既存保護。

これらの保護条件を満たさない新契約では減俸を許容するが、実成績評価下限を無視してリーグ最低額へ落としてはならない。

### 5.7 画像事例の回帰条件

次の2事例を、実成績評価下限の回帰fixtureとして追加する。

#### 事例A: 左翼手

```text
NPB一軍
出場121・打席514
打率 .281・出塁率 .307・長打率 .473・OPS .781
137安打・20本塁打・77打点・1盗塁・守備 -3
```

この成績は次を満たす。

```text
OPS .750以上 → performanceFloorD 3
20本塁打以上 → performanceFloorD 3
70打点以上 → performanceFloorD 3
```

したがって、能力由来 `d <= 0` でも年俸評価は少なくとも3とする。

左翼手の守備位置係数1.00、契約倍率1.00の場合、NPB一軍年俸は少なくとも次となる。

```text
1,600万円 + 3 × 400万円 = 2,800万円
```

新契約時に1,600万円まで下げてはならない。複数年契約中なら、そもそも契約年俸を再計算してはならない。

#### 事例B: 中堅手

```text
NPB一軍
出場121・打席514
打率 .301・出塁率 .327・長打率 .492・OPS .819
147安打・19本塁打・78打点・17盗塁・守備 +3
```

この成績は次を満たす。

```text
OPS .800以上 → performanceFloorD 6
70打点以上 → performanceFloorD 3
15盗塁以上 → performanceFloorD 1
最終下限 → 6
```

中堅手の守備位置係数1.15、契約倍率1.00の場合、NPB一軍年俸は少なくとも次となる。

```text
（1,600万円 + 6 × 400万円）× 1.15
= 4,600万円
```

新契約時に1,840万円のままにしてはならない。複数年契約中の場合は契約年俸を維持し、この成績を理由に途中改定しない。

### 5.8 実装上の注意

- `goodReal` と年俸用実成績評価で同じOPS・ERA・WHIP算出処理を重複実装しない。可能な範囲で共通ヘルパーを使用する。
- 年俸用の実成績評価値は、画面に表示された確定後の `S.lastSt` を使用する。
- 不調年・キャリア年補正後の最終成績を評価する。
- 故障全休で実成績がない場合は `performanceFloorD = 0` とし、既存の故障・契約保護に従う。
- `performanceFloorD` を殿堂評価、昇降格、能力値、海外移籍資格、大会判定へ流用しない。
- 年俸計算の理由をテスト可能にするため、必要に応じて `abilityD`、`performanceFloorD`、`awardBonus`、`salaryD` を純粋関数の戻り値として保持する。

## 6. 仕様変更4: 野手総合能力へスタミナを5%反映

### 6.1 対象

次の3分類だけを変更する。

- 捕手 `C`
- 内野手 `IF`
- 外野手 `OF`

投手 `P` は変更対象外とする。

### 6.2 投手総合能力は完全維持

投手の現行計算式を変更してはならない。

```javascript
if (S.pos === 'P') {
  const arr = [a.vel, a.ctl, a.brk].sort((x, y) => y - x);
  return Math.round(
    arr[0] * 0.42 +
    arr[1] * 0.30 +
    arr[2] * 0.18 +
    a.sta * 0.10
  );
}
```

次をすべて維持する。

- 球速・制球・変化球の高い順に `42%・30%・18%` を適用する。
- スタミナは高低順位へ参加させず、固定 `10%` とする。
- 投手の能力成長コストを変更しない。
- 先発・中継ぎ・抑えによって総合能力式を分岐させない。
- 投手のMLBオファーに必要な総合60、成績評価 `d >= 2` を変更しない。

### 6.3 野手の現行基礎評価

打撃4能力は現行どおり高い順に並べる。

```text
打撃評価
= 最高能力 × 38%
 + 2番目 × 27%
 + 3番目 × 20%
 + 4番目 × 15%
```

対象能力:

- ミート
- パワー
- 選球眼
- 走力

スタミナをこの4能力の順位へ加えてはならない。スタミナが最高値でも38%を適用しない。

守備評価式および守備比重は現行どおり維持する。

| 守備位置 | 守備比重 `dw` |
| --- | ---: |
| 遊撃手 | 0.30 |
| 中堅手 | 0.30 |
| 捕手 | 0.30 |
| 二塁手 | 0.22 |
| 三塁手 | 0.22 |
| 右翼手 | 0.20 |
| 左翼手 | 0.14 |
| 一塁手 | 0.12 |
| DH | 0.12 |

現行の守備位置別 `dpScore()`、DHの守備ペナルティ、未設定時の守備位置選択を変更しない。

### 6.4 新しい野手総合能力式

まず、丸め前の現行基礎評価を算出する。

```javascript
const base = offv * (1 - dw) + def * dw;
```

次に、基礎評価95%とスタミナ5%を合成し、最後に四捨五入する。

```javascript
let v = Math.round(base * 0.95 + a.sta * 0.05);
```

`イップス` の総合能力 `-3` は、四捨五入後に現行どおり適用する。

```javascript
if (S.traits.yips) v -= 3;
```

したがって、野手の最終式は次の意味となる。

```text
野手総合
= round（現行の打撃・守備基礎評価 × 95% + スタミナ × 5%）
  - イップス補正3（該当者のみ）
```

### 6.5 計算例

打撃・守備の丸め前基礎評価が60の場合:

| スタミナ | 新しい総合能力 |
| ---: | ---: |
| 40 | `round(60 × 0.95 + 40 × 0.05) = 59` |
| 60 | `round(60 × 0.95 + 60 × 0.05) = 60` |
| 80 | `round(60 × 0.95 + 80 × 0.05) = 61` |

スタミナは総合能力へ小さく反映するが、打撃・守備を無視して総合60へ到達できるほど高い比重を持たせない。

### 6.6 野手総合変更に伴う維持事項

- 捕手の守備評価は現行どおり `捕球40% + リード40% + 肩力20%` とする。
- 捕手の守備範囲は捕手守備評価へ追加しない。
- 内野手・外野手の各守備位置別評価式を変更しない。
- スタミナによる出場数、DH転向、打率微補正などの既存効果を変更しない。
- スタミナ以外の能力値、潜在能力、成長コスト、季前ダイス、能力点配分を変更しない。
- `ovr()` を使用するNPBドラフト、昇降格、移籍、海外オファー、大会結果、年俸などの基準値は変更しない。
- MLB直接オファーの総合60および `d >= 2` を変更しない。
- 新しい野手総合式の結果が既存の各判定へ自然に反映されること。

## 7. 実装上の共通要件

### 7.1 オファー計算の単一化

NPB復帰・国内FA・海外FAでは、画面表示と実際の契約に同じ確定済みofferオブジェクトを使用すること。

可能であれば、副作用のない共通関数へ次の処理を集約する。

- 評価値の算出
- 基準年俸の算出
- 契約倍率
- 守備位置係数
- 最低提示年俸
- 1万円単位の丸め
- 契約総額
- 現年俸との差額・増減率

ただし、今回の範囲を超える契約システム全体の大規模リファクタリングは行わないこと。

### 7.2 RNGとseed

契約年数を選択肢表示前に確定するため、v1.0.2以前と乱数呼び出し順が変わることは許容する。

ただし、v1.0.3では次を保証すること。

- 同じバージョン・同じseed・同じ選択では同じ結果になる。
- 同一オファーの年数を表示時と契約時に二重抽選しない。
- オファー選択後に年俸を再抽選・再計算しない。
- 野手総合能力式の変更自体ではRNGを追加消費しない。

### 7.3 既存契約状態

契約成立時、最低限次を同じofferオブジェクトの値で更新すること。

```text
S.currentSalary
S.ct.annualSalary
S.ct.yrs
S.ct.remainingYears
S.ct.totalValue
S.ct.mult
S.ct.contractType
```

画面表示値と内部保存値の不一致を残してはならない。
