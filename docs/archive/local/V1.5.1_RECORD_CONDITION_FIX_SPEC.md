## 1. 文書情報

- 対象作品：日本語版「野球人生シミュレーター」
- 修正後バージョン：`1.5.1`
- 基準バージョン：`1.5.0`

3. 記録画面の不自然または意味の曖昧な日本語

ゲームバランス、成績生成、傷病期間、RNGおよび固定seedのゲーム進行結果は変更しない。

## 3. BUG-REC-01 下位階級成績のMiLB誤分類

### 3.1 現象

NPB育成またはNPB二軍だけに所属している選手でも、記録画面の通算成績が次のように表示される。

```text
MiLB
出場 106｜打席 451｜打率 .297｜本塁打 15｜打点 65
```

同様に、KBO二軍およびCPBL二軍の成績もMiLBとして集計される可能性がある。

### 3.2 確認済み原因

`docs/src/engine/game.js`の現行処理は、シーズン成績を次のように集計している。

```javascript
const bucket = bucketOf(S.lv);
accStat(bucket, st);
```

`bucketOf()`は次の実装である。

```javascript
function bucketOf(lv) {
  const l = lv && LV[lv];
  return l && l.top ? l.top : 'MINOR';
}
```

一方、現行`LV`定義で`top`が指定されているのは主に一軍階級だけである。

```javascript
NPB_DEV: { ..., org:'NPB' }
NPB2:    { ..., org:'NPB' }
NPB1:    { ..., org:'NPB', top:'NPB' }

KBO2:    { ..., org:'KBO' }
KBO1:    { ..., org:'KBO', top:'KBO' }

CPBL2:   { ..., org:'CPBL' }
CPBL1:   { ..., org:'CPBL', top:'CPBL' }
```

`top`がない階級はすべて`MINOR`へfallbackする。記録画面は`MINOR`を`MiLB`と表示するため、NPB育成、NPB二軍、KBO二軍、CPBL二軍までMiLBとして表示される。

これは表示ラベルだけの問題ではなく、成績が`S.stats.MINOR`へ加算される集計不具合である。

### 3.3 正しい分類

|所属階級|成績bucket|表示名|
|---|---|---|
|NPB育成|`NPB`|NPB|
|NPB二軍|`NPB`|NPB|
|NPB一軍|`NPB`|NPB|
|KBO二軍|`KBO`|KBO|
|KBO一軍|`KBO`|KBO|
|CPBL二軍|`CPBL`|台湾プロ野球|
|CPBL一軍|`CPBL`|台湾プロ野球|
|ルーキーリーグ|`MINOR`|MiLB|
|1A|`MINOR`|MiLB|
|2A|`MINOR`|MiLB|
|3A|`MINOR`|MiLB|
|MLB|`MLB`|MLB|
|独立リーグ|`IND`|独立リーグ|
|社会人野球|`CORP`|社会人野球|

### 3.4 修正方式

各成績対象階級へ明示的な`top`を設定する。

```javascript
NPB_DEV: { ..., org:'NPB', top:'NPB' },
NPB2:    { ..., org:'NPB', top:'NPB' },
NPB1:    { ..., org:'NPB', top:'NPB' },

KBO2:    { ..., org:'KBO', top:'KBO' },
KBO1:    { ..., org:'KBO', top:'KBO' },

CPBL2:   { ..., org:'CPBL', top:'CPBL' },
CPBL1:   { ..., org:'CPBL', top:'CPBL' },

R:       { ..., org:'MiLB', top:'MINOR' },
A1:      { ..., org:'MiLB', top:'MINOR' },
A2:      { ..., org:'MiLB', top:'MINOR' },
A3:      { ..., org:'MiLB', top:'MINOR' },
MLB:     { ..., org:'MLB', top:'MLB' },

IND:     { ..., org:'IND', top:'IND' },
CORP:    { ..., org:'CORP', top:'CORP' }
```

未知または設定漏れの階級を自動的に`MINOR`へ分類してはならない。`bucketOf()`は不明な階級をテストで検出できる明確なエラーとする。

```javascript
function bucketOf(lv) {
  const level = lv && LV[lv];
  if (!level?.top) throw new Error(`UNKNOWN_STAT_BUCKET:${lv}`);
  return level.top;
}
```

実際のモジュール構造に合わせた同等実装は認めるが、fallback先を別リーグにしてはならない。

### 3.5 影響調査

次の`S.stats`参照処理をすべて調査し、正しいbucketへの変更による影響を報告する。

- リーグ別通算成績
- 年度別成績と生涯成績
- 新人王資格
- 年間表彰
- オールスター累計
- 日本野球殿堂および各国殿堂
- `teamTally`
- 引退画面とリザルト画像
- 特性および称号判定
- 固定seed snapshot

表示文字だけを`MiLB`から`NPB`へ固定変更してはならない。保存・集計bucketと表示ラベルの両方を確認する。

## 4. BUG-CON-01 リハビリ全休中の状態表示

### 4.1 現象

ホームには次のカードが表示される。

```text
リハビリ年
大けがが治らず、今季は全休確定。
```

しかし能力画面または選手詳細のコンディションでは、全休中にもかかわらず次のように表示され得る。

```text
シーズン稼働率：0%
リハビリ：なし
```

### 4.2 確認済み原因

`phasePre()`はリハビリ年開始時に次を実行する。

```javascript
if (S.rehab > 0) {
  S.rehab--;
  S.skipMid = true;
  S.seasonFactor = 0;
}
```

残り1年の場合、現在のシーズンが全休リハビリ年であっても、処理直後の`S.rehab`は0になる。

しかし`buildAbilityViewModel()`および`buildPlayerDetailViewModel()`は、主に`S.rehab > 0`だけでリハビリ中かを判断している。そのため現在進行中の全休状態を表示できない。

### 4.3 現在状態の判定

現在が全休リハビリ年かどうかは、少なくとも次の既存状態を組み合わせて判断する。

```javascript
const isRehabSeason =
  S.skipMid === true &&
  S.seasonFactor === 0;
```

`S.rehab`は今季開始時の減算後に残る将来期間、`isRehabSeason`は今季が実際に全休中かを示すものとして表示上区別する。

### 4.4 表示優先順位

|条件|表示|
|---|---|
|`isRehabSeason && S.rehab > 0`|`リハビリ中（今季全休・残り○年）`|
|`isRehabSeason && S.rehab === 0`|`リハビリ中（今季全休）`|
|`!isRehabSeason && S.rehab > 0`|`残り○年`|
|それ以外|`なし`|

能力画面と選手詳細画面は、同一条件から同じ現在状態を表示する。副作用のない共通表示関数へまとめてもよい。

### 4.5 表示項目の時間範囲

現在値と生涯累計を区別するため、次の文言を変更する。

```text
大きな故障 → 大きな故障（通算）
```

各項目の意味は次のとおりとする。

|項目|対象期間|
|---|---|
|スタミナ|現在値|
|シーズン稼働率|現在シーズン|
|次回故障リスク加算|次回傷病判定|
|今季一時故障リスク加算|現在シーズン|
|大きな故障（通算）|キャリア累計|
|リハビリ|現在の全休状態と残存期間|

過去に全休し、現在は復帰済みの場合、次の表示は正常である。

```text
シーズン稼働率：100%
リハビリ：なし
大きな故障（通算）：1回
```

過去の全休は年度別履歴に残し、復帰後も現在状態へ「リハビリ中」と表示し続けてはならない。

### 4.6 修正範囲

今回は表示判定だけを修正する。次を変更しない。

- `S.rehab`を減算する時期
- `S.skipMid`および`S.seasonFactor`のゲーム処理
- リハビリ年数
- 全休期間
- 傷病確率
- 能力低下
- 契約・年俸への傷病影響

## 5. UI-TXT-01 記録画面の文言

現行`docs/src/ui/record-view.js`の次の文言を変更する。

|現行|変更後|理由|
|---|---|---|
|`競技シーズン`|`プレー年数`|高校・大学・社会人・プロを含む経過年数として理解しやすい|
|`競技別通算`|`リーグ別通算成績`|NPB、KBO、CPBL、MiLB、MLBは異なる競技ではなくリーグ・区分である|

関連するHTML、JavaScript、テストおよび設計書内の旧文言も検索して更新する。

`プレー年数`の値は現行`S.log.length`を維持し、本修正では計数方法を変更しない。計数内容に別の問題が見つかった場合は無断で修正せず報告する。

- 昇格・降格、移籍、契約、年俸

- イベント内容、順序、成功率、結果
