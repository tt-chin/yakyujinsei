# v1.5.2 情報構造・画面統合 修正仕様書

## 1. 文書情報

- 対象作品：日本語版「野球人生シミュレーター」
- 修正後バージョン：`1.5.2`
- 基準バージョン：`1.5.1`
- 修正種別：UI情報構造・重複表示修正・階級別通算成績追加
- 調査対象：GitHub `tt-chin/yakyujinsei`の`dev`ブランチ
- 調査基準コミット：`e2bf38cfcc7608f1c78203df6dbf4b927651ff9a`
- 調査日：2026年9月4日
- 状態：現行監査完了・実装可能

本書は、v1.5.1までに実装されたホーム、能力、記録、選手詳細の情報を再監査し、同じ情報の重複表示と不必要な画面分割を解消するための修正仕様である。

v1.5.1で修正したリーグ別成績bucketおよびリハビリ状態表示は実装済みの基準として維持する。そのうえで、既存bucketをゲーム判定用のリーグ集計として残し、表示用に階級別通算成績を追加する。

## 2. 目的

現行の4メインメニューを、利用目的に合わせた3メインメニューへ整理する。

```text
現行：ホーム｜能力｜記録｜選手詳細
変更：ホーム｜選手｜キャリア
```

各情報に一つの主要表示場所を割り当て、同じ値を概要と詳細へ重複表示しない。

本修正は情報の配置と表示責務を整理し、表示用の階級別通算成績を追加する。既存状態の意味、計算式、イベント、年度成績、契約、傷病、RNGおよび固定seedのゲーム進行結果は変更しない。状態`S`への追加は、本書で定義する`S.statsByLevel`だけを例外として許可する。

### 3.3 コンディションの経緯

現行`record-view.js`にはコンディション表示が存在しないため、記録画面からの表示欠落ではない。

コンディションは当初`player-detail.js`の「特性」内へ配置され、その後「育成・行動」を「能力」へ変更した際に`ability-view.js`へも追加された。元の「特性」側を削除しなかったため重複したものである。

### 3.4 生涯総収入の経緯

`record-view.js`のキャリア概要と`player-detail.js`の契約・収入は、どちらも同じ`S.careerEarnings`を表示する。概要と詳細の意図で作られたが、値も意味も同じであり、二箇所へ残す必要はない。

### 3.5 通算成績の集計粒度

現行の`S.stats`は、所属階級を次の上位bucketへ統合している。

- `NPB_DEV`、`NPB2`、`NPB1` → `NPB`
- `KBO2`、`KBO1` → `KBO`
- `CPBL2`、`CPBL1` → `CPBL`
- `R`、`A1`、`A2`、`A3` → `MINOR`
- `MLB`、`IND`、`CORP` → 各単独bucket

この構造はリーグ単位のゲーム判定には必要だが、NPB育成、NPB二軍、NPB一軍などの各階級で残した成績を画面上で区別できない。v1.5.2では`S.stats`を変更せず、表示用の`S.statsByLevel`を追加して同じ年度成績を階級単位でも累積する。

## 4. 新しいメイン情報構造

### 4.1 メインメニュー

```text
ホーム｜選手｜キャリア
```

|メイン画面|利用目的|内容|
|---|---|---|
|ホーム|ゲームを進める|操作、選択肢、結果、進行履歴|
|選手|現在の選手を確認する|能力、潜在能力、現在のコンディション、特性|
|キャリア|これまでの経歴を確認する|通算成績、実績、契約・収入、年度別|

### 4.2 メイン画面を3つにする理由

- 「能力」と「選手詳細・特性」はどちらも現在の選手状態であり、一つにまとめられる
- 「記録」と「選手詳細・実績／契約／年度別」はどちらもキャリア情報であり、一つにまとめられる
- 4つのメイン画面を維持するより、利用目的が明確になる
- モバイルでメインナビゲーションのボタン幅を確保できる
- 同じ情報を複数画面に置く理由がなくなる

## 5. 固定ヘッダーの責務

固定ヘッダーは、ゲーム中に常時必要な現在情報だけを表示する。

|情報|表示|
|---|---|
|選手名|維持|
|ポジション・選手タイプ|維持|
|現在所属|維持|
|年齢|維持|
|年度|維持|
|総合|維持・唯一の表示場所とする|
|現在年俸|維持・唯一の単独表示場所とする|
|シーズン段階|維持|
|年俸内訳への導線|維持|

能力画面の総合、記録画面の所属、契約画面の現在年俸は削除する。

契約scheduleや年俸履歴の一部として同じ年度の金額が必要になる場合は、履歴・契約文脈として表示してよい。ただし「現在年俸」という同一概要項目を別画面に再表示しない。

## 8. キャリア

### 8.1 サブタブ

```text
通算成績｜実績｜契約・収入｜年度別
```

既定タブは「通算成績」とする。

### 8.2 通算成績

表示する情報：

- プレー年数
- 階級別通算成績
- 国際大会の通算成績または、現行で詳細成績を表示できない場合は出場大会数

表示しない情報：

- 現在所属（固定ヘッダーに表示済み）
- 表彰・主要実績の件数（実績タブに一覧表示する）
- 生涯総収入（契約・収入タブに表示する）

現行「キャリア記録」概要カードは、上記の重複項目を削除したうえで「プレー年数」と必要な国際記録だけを通算成績の冒頭に統合する。情報が一項目だけになる場合、独立した概要カードを作らず階級別通算成績と同じpanelに配置してよい。

#### 8.2.1 表示名称と階層

画面上の見出しは「リーグ別通算成績」ではなく「階級別通算成績」とする。リーグ名をグループ見出し、階級名を成績行として、原則として上位階級から表示する。

|グループ|表示する階級|内部キー|表示順|
|---|---|---|---:|
|NPB|NPB一軍|`NPB1`|1|
|NPB|NPB二軍|`NPB2`|2|
|NPB|NPB育成|`NPB_DEV`|3|
|KBO|KBO一軍|`KBO1`|1|
|KBO|KBOフューチャース|`KBO2`|2|
|台湾プロ野球|台湾プロ野球一軍|`CPBL1`|1|
|台湾プロ野球|台湾プロ野球二軍|`CPBL2`|2|
|MLB|MLB|`MLB`|1|
|MiLB|3A|`A3`|1|
|MiLB|2A|`A2`|2|
|MiLB|1A|`A1`|3|
|MiLB|ルーキーリーグ|`R`|4|
|独立リーグ|独立リーグ|`IND`|1|
|社会人野球|社会人野球|`CORP`|1|

- 成績が一度も記録されていない階級は表示しない
- 一つも成績行がないグループ見出しは表示しない
- グループ合計は同じ画面へ併記しない。階級別とリーグ合計の重複表示を避ける
- 打者と投手は現行の成績項目・書式をそのまま使用する
- 年度別タブの「当時の所属・階級」と内部キーの対応を一致させる

#### 8.2.2 既存リーグ集計の維持

v1.5.1で修正した`S.stats`のbucket分類を変更しない。

- NPB育成、NPB二軍、NPB一軍 → `S.stats.NPB`
- KBO二軍、KBO一軍 → `S.stats.KBO`
- CPBL二軍、CPBL一軍 → `S.stats.CPBL`
- R、1A、2A、3A → `S.stats.MINOR`
- MLB、独立リーグ、社会人野球 → 各既存bucket

`S.stats`は従来どおり、表彰、殿堂、成績条件その他の既存ゲームロジックが参照するリーグ単位の集計とする。階級表示を追加するために既存参照先を`S.statsByLevel`へ一括置換してはならない。

#### 8.2.3 階級別状態

状態`S`へ次を追加する。各値の初期形は既存の成績bucketと同じ形式を使用し、未記録状態を既存実装が`null`以外で表す場合はその形式へ合わせる。

```javascript
statsByLevel: {
  NPB1: null,
  NPB2: null,
  NPB_DEV: null,
  KBO1: null,
  KBO2: null,
  CPBL1: null,
  CPBL2: null,
  MLB: null,
  A3: null,
  A2: null,
  A1: null,
  R: null,
  IND: null,
  CORP: null
}
```

年度成績`st`を確定した時点の所属階級キーを使い、同一の`st`を次の二箇所へ累積する。

1. 既存のリーグ集計`S.stats[bucket]`
2. 新しい階級集計`S.statsByLevel[levelKey]`

成績を二度生成してはならない。階級別集計のためのRNG呼出しも禁止する。共通の加算処理を利用し、同じ確定済み成績を二つの集計先へ加算する。

所属変更がシーズン終了処理より後に行われる場合、成績生成時点の`levelKey`を保持して加算し、移籍・昇格・降格後の所属へ誤って記録しない。現行データに一シーズン内の正確な成績分割が存在しない場合は推測分割せず、現行の年度成績が確定した階級へ全量を記録する。

#### 8.2.4 集計整合性

階級別集計の合計は、対応する既存リーグbucketと一致しなければならない。

```text
S.stats.NPB   = NPB1 + NPB2 + NPB_DEV
S.stats.KBO   = KBO1 + KBO2
S.stats.CPBL  = CPBL1 + CPBL2
S.stats.MINOR = A3 + A2 + A1 + R
```

`MLB`、`IND`、`CORP`は既存bucketと階級別bucketが一対一で一致する。比較は打者・投手それぞれの全累積項目に対して行い、小数イニングは既存の丸め規則を使用する。

本ゲームはseed-onlyで途中状態を永続保存しないため、過去の統合済み成績を現在所属から階級別へ推測移行しない。v1.5.2で開始したゲームは初年度から`statsByLevel`へ記録する。旧状態をテストへ注入する場合は空の`statsByLevel`を安全に初期化し、過去分を架空の階級へ割り当てない。

### 8.3 実績

- 表彰
- 優勝
- 主要実績
- 日本代表実績
- 殿堂関連の確定済み結果

件数だけの概要は表示せず、現行の実績一覧を唯一の表示場所とする。新しい表彰判定や集計を追加しない。

### 8.4 契約・収入

表示する情報：

- 現契約の種別
- 契約開始年・終了年
- 契約残年数
- 保証総額、年度schedule等、現行状態に存在する契約情報
- 生涯総収入
- 現行の契約・年俸決定履歴

表示しない情報：

- 「現在年俸」という単独項目（固定ヘッダーに表示済み）
- ヘッダーと同じ年俸内訳ボタンの重複配置

年俸内訳は固定ヘッダーの「年俸の内訳を見る」を唯一の入口とする。既存dialogとcontrollerを再利用し、キャリア画面内に同じdialogを複製しない。

生涯総収入はこのタブだけに表示し、通算成績から削除する。

### 8.5 年度別

- 年度
- 年齢
- 当時の所属・階級
- 当時の役割または守備位置（現行年度記録に存在する場合）
- 年度成績
- 年度年俸（現行年度記録に保存済みの場合だけ）

存在しない履歴値を現在値から推測して追加してはならない。状態に年度年俸が保存されていない場合、本版で新しい履歴状態を追加せず、現行4列を維持する。

## 10. DOM・UI状態

### 10.1 メインview

```text
home
player
career
```

旧`ability`と`record`を独立main viewとして残さない。旧`player`の内容は新しい「選手」と「キャリア」へ責務分割する。

### 10.2 UI状態

```javascript
const uiState = {
  activeMainView: 'home',
  activePlayerTab: 'ability',
  activeCareerTab: 'stats'

```

- UI状態を状態`S`へ追加しない
- URL、seed、共有情報へ保存しない

- 「選手」の既定タブは`ability`
- 「キャリア」の既定タブは`stats`
- タブ変更でゲーム関数またはRNG関数を呼ばない

### 10.3 実装上の制約

- 同一IDのDOMを複製しない
- 既存DOMの再配置時にevent listenerを消失させない
- `innerHTML`の再代入でゲーム操作DOMを破棄しない
- UIモジュールから`game.js`への逆importを追加しない
- view modelは読取専用とする
- 旧`ability`、`record`、旧詳細タブ名への参照をHTML、JavaScript、CSS、テスト、設計書から調査する
- ファイル名は現行モジュールを再利用しても、責務に合わせて統合してもよいが、循環依存を作らない

### 10.4 成績状態の責務

|状態|責務|主な利用先|
|---|---|---|
|`S.stats`|既存リーグbucketの通算集計|ゲーム判定、表彰、殿堂、既存条件|
|`S.statsByLevel`|所属階級ごとの通算集計|キャリア・階級別通算成績の表示、整合性検証|
|年度別記録|年度ごとの確定成績と当時の所属|キャリア・年度別|

`record-view.js`または統合後のキャリア表示モジュールは`S.statsByLevel`を読取専用で参照する。表示時に集計値を書き換えたり、年度別記録から毎回再計算したりしない。

## 11. アクセシビリティ・モバイル

- メインナビゲーションは3等分し、PC・モバイルで横スクロールを発生させない
- 現在のメイン画面に`aria-current="page"`を付与する
- サブタブに`role="tablist"`、`role="tab"`、`role="tabpanel"`を使用する
- 選択中タブに`aria-selected="true"`を付与する
- 非表示panelに`hidden`を使用する
- 色だけで選択状態を示さない
- キーボード操作とタップ操作の両方を維持する
