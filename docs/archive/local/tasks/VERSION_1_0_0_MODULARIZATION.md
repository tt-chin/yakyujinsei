# バージョン1.0.0 モジュール化タスク仕様書

- 状態：計画フェーズ開始可能
- 対象：seed-only方式へ更新済みの現行バージョン1.0.0
- 基準実装：リポジトリの現行 `index.html`
- 基準仕様：現行 `YaKyoLife_詳細設計書.md`
- 恒久ルール：リポジトリ直下の `AGENTS.md`

## 1. 目的

単一の `index.html` に含まれているバージョン1.0.0のCSSとJavaScriptを、GitHub Pagesでそのまま配信できるES Modules構成へ分割する。

今回の目的は保守性の改善だけであり、ゲーム仕様、翻訳、UI、乱数結果を変更することではない。完成後もプレイヤーから見えるバージョン1.0.0の挙動は同一でなければならない。

## 2. 対象外

- 旧台湾版の差分導入
- JP4または新仕様の実装
- ゲームバランス調整
- 文言や翻訳の改善
- UI再設計、DOM順序変更
- 状態管理の全面刷新
- TypeScript化、フレームワーク導入
- npm、bundler、ビルド工程、サーバー処理の導入
- 過去ルールを再現する複数エンジンの保持

旧台湾版は将来の更新候補を確認する参考資料に限る。今回のモジュール化へ混ぜない。

## 3. 絶対に維持する互換条件

以下はコードの移動・分割だけに留め、値、順序、判定、表示を変更しない。

- ゲーム進行、フェーズ順、イベント順、選択肢順
- 表示文、承認済み翻訳、称号、ネット用語
- HTML要素、ID、class、DOM順序、主要レイアウト
- 初期能力、能力配分、成長、衰退、故障
- 各リーグ・階層の平均値と最低値
- 成績生成、昇降格、戦力外、強制引退
- 年俸、契約、FA、海外移籍、MiLB経路
- 優勝、賞、引退、名人堂、最終集計
- 結果画像と共有操作
- 乱数アルゴリズム、呼び出し順、消費回数

同一seed・同一入力では、モジュール化前後の結果が一致することを必須とする。

## 4. seed-only共有仕様

モジュール化後も次を厳守する。

```text
共有URL：?seed=<SEED>
製品バージョン：VERSION = '1.0.0'
```

- URLへ `rv` と `rules` を出力しない。
- 固定GitHub Pagesドメインを埋め込まず、現在のページURLを基準に生成する。
- `?seed=...&rv=...&rules=...` のような旧URLを受け取った場合もseedだけを使用する。
- `rv` と `rules` の値による拒否、分岐、旧版再生を行わない。
- `UNSUPPORTED_REPLAY_VERSION` を復活させない。
- ゲーム更新後に過去と完全同一の人生を保証しない。
- seedの正規化、コピー、同一seed再開始が現行seed-only実装と一致すること。

## 6. 提案するモジュール構成

これは計画作成時の出発点であり、現行コードの実責務に合わせて統合・名称変更してよい。ただし空ファイルや一関数だけの過剰分割は行わない。

```text
index.html

styles/
  base.css
  layout.css
  components.css
  mobile.css

src/
  config.js

  core/
    rng.js
    state.js
    utils.js

  data/
    abilities.js
    teams.js
    leagues.js
    traits.js
    events.js

  engine/
    ability.js
    season.js
    injury.js
    championship.js
    awards.js
    contract.js
    career.js
    draft.js
    international.js

  flow/
    phases.js
    events.js
    love.js

  ui/
    dom.js
    board.js
    allocation.js
    timeline.js
    traits.js
    retire.js
    share-image.js
    preferences.js

  main.js
```

分割原則：

- `config.js`：内部バージョン、変更されにくい全体設定
- `core/`：RNG、状態、汎用で副作用の少ない処理
- `data/`：静的データ定義
- `engine/`：ゲーム判定・計算
- `flow/`：フェーズ遷移とイベント進行
- `ui/`：DOM表示、入力、画像、共有操作
- `main.js`：起動、依存の組立、初期イベント登録

データと処理を機械的に分けた結果、循環依存や大量の引数受け渡しが増える場合は、互換性と可読性を優先して同一モジュールに保つ。

## 7. 実装上の制約

- ブラウザ標準の `<script type="module">` を使用する。
- GitHub Pagesでビルドなしに動作させる。
- import、CSS、画像等はすべて相対パスを使う。
- UTF-8を維持する。
- 読込順に依存する処理は `main.js` から明示的に初期化する。
- モジュール評価時の副作用を最小化し、イベント登録の重複を起こさない。
- RNGをラップし直したり、配列処理へ置換したりして呼び出し回数を変えない。
- オブジェクト列挙順、sortの比較条件、丸め順、評価順を変えない。
- `Math.random()`、seeded RNG、日時依存処理の全箇所を把握してから移動する。
- `S` を複製して複数の真実源を作らない。
- CSS分割で詳細度、読込順、メディアクエリの結果を変えない。
- 依頼外の命名変更、整形、dead code削除、最適化を同時に行わない。

## 8. 検証項目

### 8.1 静的検証

- 全JavaScriptの構文が有効
- 全import/exportが解決
- HTML、CSS、JSの相対参照に404なし
- 循環依存による未初期化エラーなし
- コンソールに例外・警告の増加なし
- 固定ドメイン文字列なし
- URL生成コードに `&rv=`、`&rules=` なし
- `UNSUPPORTED_REPLAY_VERSION` なし
- 内部の `VERSION = '1.0.0'` は存在

### 8.2 seed-only検証

- 新規開始でseedが生成される
- コピーURLが `?seed=<SEED>` だけになる
- 同一seedで再開始できる
- seedの手入力・正規化が現行と同じ
- 旧形式URLからseedだけを使用する
- 不正な `rv`・`rules` があってもそれを理由に拒否しない
- URLの基準が現在の配信先であり、固定ドメインではない

### 8.3 固定seed回帰

最低でも投手3ケース、野手3ケースを用意し、モジュール化前後を同じ入力で比較する。各ケースで可能な限り次を記録する。

- 初期能力と初期状態
- サイコロ結果と能力配分
- 発生イベント、選択肢、選択結果
- 年ごとの能力、成績、成長、衰退、故障
- 所属球団・リーグ・階層
- 昇格、降格、戦力外、契約、年俸
- 国内外移籍、FA、MiLB・MLB経路
- 優勝、賞、称号、恋愛等のイベント
- 引退年齢・引退理由
- 最終通算成績と名人堂判定
- RNG呼び出し回数または同等の消費位置指標

差分が出た場合、「seed互換を保証しない」という共有URL方針を理由に許容してはならない。今回のモジュール化自体は同一コードの構造変更なので、モジュール化前後の同一seed結果を一致させる。

### 8.4 実動画面

PC幅とモバイル幅で次を確認する。

- 開始画面と選手作成
- ポジション選択
- サイコロ、能力配分、確定
- イベントカード、選択肢、結果表示
- シーズン進行とタイムライン
- 契約・移籍等の分岐
- 引退と最終結果
- 結果画像の作成
- URLコピーと同一seed再開始
- レイアウト崩れ、二重クリック、イベント多重登録がない

長い確率分岐を実動で発生させられない場合は、テスト用の安全な観測方法または関数単位検証を併用し、未実動項目を最終報告で区別する。
