## 2. 已確認的根本原因

[game.js](../src/engine/game.js)的現行位置如下；實作前需重新核對，不依舊行號盲目修改。

- `phasePre()`約825行：「全力投球」callback寫入`S.effort='全力投'`。
- `proSeason()`約1295行：補正對照表只識別`全力投球`／`通常投球`／`省エネ投球`，未知值回退`em=0`。
- `tjAccrue()`約280行：同樣只識別上述三個值，未知值回退倍率1.0。
- 結果：UI顯示成績重視、TJ×1.25，但實際落入通常投球的補正與負擔。
- 100條自然生涯觀測的1131筆職業階層球季快照均為`effort='全力投'`。這是本輪策略的實測證據，不代表所有玩家或所有操作路線都選全力。

沒有確認成績公式或TJ係數錯誤；問題在選項callback的資料傳遞。

## 4. 修正後應接入的既有效果

### 4.1 成績補正

條件仍是`S.pos==='P' && S.seasonFactor>0`，強度補正區塊應讀到`em=1`：

- `st.d += 1`。
- `st.era = clamp(st.era - 0.25, 1.40, 9.90)`。
- `st.ER = Math.round(st.era * st.IP / 9)`。
- `st.SO = Math.round(st.SO * 1.06)`。

這是既有程式，不是新增公式。不要重跑`simSeason()`或重新抽選，不能直接修改最終保存成績來假裝callback已修復。

注意：巔峰或事件可能使進入補正區塊前的ERA低於1.40；既有clamp仍會將其限制至1.40，不能為保證「永遠降低0.25」而改clamp。

成績處理順序保持：原始季成績及好不調→安全限制→事件成績→投球強度→既有後續normalize→累積／保存／顯示。若事件點數非0，最終ERA仍可能由`ER×9/IP`重新計算，不強迫最終顯示值剛好減少0.25。

### 4.2 TJ負擔

条件仍是投手且`seasonFactor>0`：

```text
增加量 = (vel + brk) / 19 × 1.25 × (tjCount >= 1 ? 1.15 : 1)
```

不另乘健康比例、不改rubber的50／100上限，也不改門檻使用`>=`的既有判定。

同一個有效球季仍只累積一次。這個區塊本身不得新增RNG。跨過上限後由既有`tjGamble()`處理能力降低、選項及後續操作。

### 4.3 全休與其他位置

- 全休年度維持既有跳過投球強度選項／不套成績補正／不增加TJ的流程。
- 野手不出現投球強度選項，也不適用本補正。
- 部分受傷年度仍依既有`seasonFactor>0`條件處理；不自行增加倍率縮放。

## 5. 固定Seed與RNG相容邊界

**以下結果差異必須在實作前由使用者批准；本設計書本身不算批准。**

### 5.1 必須保持不變

- 主RNG演算法、直接呼叫點及抽選順序，不新增或刪除R／chance／ri。
- 點擊強度選項本身消耗RNG為0；`preAsk()`及其原有訓練抽選仍照常執行，不能將整個callback誤稱RNG0。
- 同一控制輸入下的`simSeason()`原始輸出與R序列不變。
- 單獨成績強度补正與`tjAccrue()`新增RNG均為0。
- 沒有選全力的投手路線，以及野手路線，排除VERSION後完整S、選擇與RNG應一致。
- 同修正版、同Seed、同實際操作歷史，完整生涯必須可以重播。

### 5.2 允許但必須追蹤的差異

- 全力選項後，`S.effort`由錯值變成canonical值。
- 既有補正導致最終成績／TJ變化。
- 由上述成績與TJ差異自然觸發的既有獎項、薪資、降格、手術／注射、能力、契約、退休及後續分支差異。
- 條件分支不同後，完整生涯RNG總消耗與後續取值位置可能不同；不能宣稱新旧人生RNG總次數必然相同。

比較應定位第一個差異，證明它來自全力選項或既有補正，再記錄首次分支差異及其RNG影響。不得大範圍忽略stats、金錢、traits、契約或全部S，使比較表面通過；不得回滾／補抽主RNG以強求舊人生相同。

舊版全力路線不是修正後的全狀態一致控制組。保留其原始記錄作負面證據；另一組以真實UI選通常投球作修正前後不變控制。
