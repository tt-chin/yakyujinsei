## 3. 全批次共通規格

### 3.1 排版與斷點

以下為日文版建議起始值，不是 My Baseball Days 的複製值。第 0 批核對後可修正，但需在 PR 說明理由。

| 範圍 | 目標版面 | 捲動策略 |
|---|---|---|
| 首頁，所有寬度 | 頁首＋單張創角／存檔卡＋功能區 | 整頁自然捲動，不鎖 100dvh |
| 遊戲 ≥1100px 且高度 ≥700px | 左側 280–320px，右側彈性主欄 | 外框受控高度，側欄與主閱讀區各自捲動 |
| 遊戲 <1100px | 上方摘要與導覽，下方事件及決策 | 自然頁面捲動；操作區可收合，以原地 sticky 入口協助返回 |
| 任意寬度高度 <700px | 短視窗模式 | 取消桌面固定高度與內部捲動限制，回自然捲動 |
| 手機配點 | 專用配點路由／視圖 | 一個主捲動區，底部確認列可 sticky |

手機不照搬參考站的「高度固定＋事件區與選項區搶剩餘空間」。底部操作區表示內容閱讀順序在事件之後，並不表示所有狀態一律 fixed 在視窗底部。

桌面外框最大寬建議 1440px，左右留白 16–24px；手機頁面左右留白 12–16px；欄距 16px。主欄需 `min-width: 0`，受控高度的 Grid 子元素需 `min-height: 0`。

### 3.2 視覺與基本元件

| 項目 | 建議規格 |
|---|---|
| 主色 | 沿用現有紅色；危險操作另以警告文案與圖示區分 |
| 標題 | 首頁 clamp 約 26–40px，遊戲事件 18–22px |
| 本文 | 預設 16px，行高 1.7–1.8；設定放大時隨內容重排 |
| 副文 | 13–14px，避免用超小字塞內容 |
| 間距 | 4／8／12／16／24／32px 為主要尺度 |
| 圓角 | 一般卡片 12–16px；按鈕 10–12px |
| 觸控 | 主要互動至少 44×44 CSS px；長文選項允許自動增高 |
| 字型 | 沿用現有日文字型堆疊；數字可用 tabular-nums |
| 焦點 | focus-visible 清楚外框，不以 hover 代替 |
| 動畫 | 僅輕量狀態轉換；支援 prefers-reduced-motion |
| 模糊 | 可選增強效果；關閉 blur 時仍須清楚，不依賴模糊維持對比 |

不要對整張卡片或根容器設定 `opacity`，避免文字跟著變淡。改用具 alpha 的背景色，並減少同一區域重疊多張半透明面板。

### 3.3 語意、狀態與資料原則

遊戲狀態是唯一資料來源；版面 class、按鈕文字與階段標籤只反映狀態，不反過來用 DOM 文案推測遊戲進程。

| 狀態類型 | 內容 | 保存位置原則 |
|---|---|---|
| 遊戲狀態 | 年份、事件、能力、合約、已確認選擇、seed/RNG | 沿用現有存檔流程與格式 |
| 待確認操作 | 骰子投入、配點進度、可復原紀錄 | 沿用既有草稿語意；如需新增須定義生命周期 |
| UI 狀態 | 分頁、收合、捲動、開啟選單、焦點 | 記憶體或現有 UI 設定；不消耗遊戲 RNG |
| 使用者偏好 | 主題、字級等 | 沿用既有設定儲存，不混入角色數值 |

使用原生 button、明確 label、aria-expanded／aria-controls。分頁若採 ARIA tabs，就完整實作 tablist、tab、tabpanel 與方向鍵；否則用導覽按鈕與 aria-current，不只加一半語意。

## 5. 第 1 批：首頁與開始流程

### 5.1 頁面順序與尺寸

依序為：精簡標題與版本→短介紹／球場景觀區→創角或存檔卡→詳細設定→2×2 功能→作者資訊。

手機頁首可從約 140–200px 高的景觀區起調整，標題不採巨大棒球圖示；短螢幕改內容自然高度。這是構圖起始值，不是強制留空高度。不要為了要求首屏塞完所有東西而縮字或縮按鈕。

首頁內容最大寬建議 960px，操作卡最大寬約 560px、置中；電腦仍能看到兩側球場，手機卡片有左右留白。

標題「野球人生シミュレーター」允許自然或設計過的換行，避免固定大字導致「シミュレ／ーター」之類不自然拆字。版本號獨立為次要文字，不插入標題同一行。

### 5.2 背景分層

| 層 | 實作方向 | 預期效果 |
|---|---|---|
| 球場圖 | ES CON FIELD 既有圖，cover；手機另設 focal point 變數 | 保留球場辨識度 |
| 漸層遮罩 | 頁首較透明，靠近文字區較深；只影響背景 | 標題與場景同時清楚 |
| 根容器 | 透明，不再鋪整頁深綠實底 | 卡片外露出背景 |
| 操作卡 | 背景 alpha 約 .88–.96 起調；少量邊框與陰影 | 表單維持可讀 |

焦點位置以本壘、內野及玻璃牆取景實際比較後決定，不直接照抄參考站的 58%。不要求直向 cover 能顯示完整橫圖。若既有圖片版本已足夠，不為本批另做素材。

クレジット頁保留已核對的作者、來源、授權連結與修改說明；首頁、選單與彈窗標題統一為「クレジット」，不得因版面調整刪除署名資料。

### 5.4 有存檔：簡潔的兩個選擇

使用既有有效性檢查，只有可恢復生涯才進入此狀態。主卡顯示 `続きから` 與 `新しく始める`；不顯示長篇保存原理、保存日期、球員摘要或「可以繼續」說明段落。

按 `続きから` 使用既有恢復行為，不暗示能恢復未保存到的季中操作。按 `新しく始める` 先展開創角；**不立刻刪存檔**。只有在玩家提交新生涯、確定將覆蓋舊檔時，沿用或補上一次明確確認。

確認文案：`新しい人生を始めると、現在のセーブデータが上書きされます。`；選擇 `キャンセル／始める`。取消保留舊檔與已輸入的創角資料，不啟動 RNG。

刪除入口放進既有資料管理／設定，使用清楚的 `セーブデータを削除`。刪除前確認，成功後清除當前存檔 UI 狀態與相關快取，回普通首頁。**不顯示「削除しました」卡片、toast 或後續說明段落。**刪除失敗時才提供可理解的錯誤；不錯誤宣告無存檔。

## 10. 建議的 DOM 與 CSS 實作方向

以下是責任分層示意，名稱供參考，實作應優先沿用既有元件與 ID，不把整份頁面重寫成另一套框架。

| 元件責任 | 內容 | 注意事項 |
|---|---|---|
| StartScreen | 頁首、存檔分支、創角、2×2 功能 | 根容器透明、自然捲動 |
| GameShell | header、sidebar、main | 只負責排版，不抽事件 |
| PlayerSummary | 共用資料的桌面側欄／手機摘要 | 格式化共用，避免多次計算 |
| GameNavigation | 三分頁與返回決策 | 導航不重建 pending state |
| EventReader | 最新事件與歷史 | 長文、結果與可展開內容 |
| DecisionPanel | 問題、選項、收合 | 訂閱待決策資料，不靠 DOM 抓文字 |
| AllocationView | 草稿、預覽、還原、確認 | 單一草稿擁有者 |
| SettingsSheet | 既有偏好與工具 | 焦點與 inert 管理 |

CSS 建議以 root tokens、layout、component、state、responsive 分段；狀態使用清楚 class 或 data attribute。避免 `#app#app` 這類刻意加權方式。不得用全域 `overflow:hidden` 掩蓋水平溢出，應修正造成溢出的元件。

畫面尺寸切換不得重建配點或 pending decision；只是改版面。若手機／桌面各渲染不同摘要，禁止同名 ID、重複綁定或同時可聚焦的隱藏控制項。

## 11. 測試矩陣與通過條件

### 11.1 裝置與尺寸

| 類別 | 測試尺寸／環境 | 檢查重點 |
|---|---|---|
| 最小手機 | 320×568 | 姓名＋骰子、2×2、長選項與最後一個按鈕 |
| 一般手機 | 375×667、390×844 | 首頁構圖、事件、設定與配點 |
| 橫向短視窗 | 844×390、1024×600 | 自然捲動 fallback，不壓縮閱讀區 |
| 平板 | 768×1024 | 單欄最大寬與導航 |
| 桌面 | 1280×720、1440×900 | 雙欄、側欄與操作區 |
| 放大 | 桌面 200% 瀏覽器縮放、應用大字級 | 重排、焦點可見、無被裁掉的操作 |
| 實機 | iPhone Safari；Android Chrome | 軟鍵盤、safe-area、瀏覽器工具列與返回 |

模擬 viewport 與縮放測試須分別記錄；桌面 Chromium 通過不能寫成 iPhone 實機通過。無法執行者明列待驗證。

### 11.2 有意義的自動化檢查

- 無存檔首頁不渲染保存說明；有效檔提供繼續；刪除後回無檔狀態。
- 有檔展開新生涯但取消提交，原檔不變；刪除失敗保留狀態。
- 姓名骰子不提交；手改後遊戲取得同名；隨機來源與遊戲 RNG 分離。
- 同一 seed／設定／遊戲選擇，插入分頁、選單、收合及主題操作後，遊戲結果與 RNG state 仍一致。
- 配點草稿可跨頁；還原／重設完整；確認快速連點只生效一次。
- 所有 viewport 主要操作可見或可捲動取得；表格局部水平捲動不使整頁溢出。

檢查狀態轉移與玩家結果，不寫只比對 CSS 字串、沒有行為價值的測試。視覺驗收使用實際畫面及 computed style。

### 11.3 每批交付紀錄

每批 PR 記錄：修改問題與結果、實際修改檔案、桌面／手機前後畫面、執行的命令與結果、未測項目、存檔及 seed 相容性、回退方式。資料與截圖使用測試角色，勿混入真實使用者存檔。

## 12. 風險、回退與發布規則

| 風險 | 控制方式 |
|---|---|
| 舊 DOM 監聽被換掉後失效 | 保留入口或統一事件委派，檢查一次點擊只觸發一次 |
| UI 重繪重算隨機結果 | 引擎與 render 分離，UI 行為不呼叫遊戲 RNG |
| 新舊配點狀態並存 | 單一草稿與單一確認入口，訓練 ID 防重複 |
| 改 CSS 導致其他頁失效 | 元件作用域、代表場景回歸、最終 computed style 核對 |
| 新畫面誤覆蓋存檔 | 新生涯真正提交前才覆蓋，錯誤時不清原檔 |
| 手機 footer／sheet 遮文字 | safe-area＋內容補白、短視窗自然流、實機驗證 |
| 回退版本讀不了新存檔 | UI 批次優先不改格式；必要格式改動獨立版本與遷移設計 |

各批使用獨立提交／PR，不混入引擎平衡改動。沿專案目前 dev→測試→main→既有發布 CI 流程；第 0 批確認實際流程，避免依舊記憶假定分支規則。設計書本身不代表正式部署授權。

若一批失敗，回退該批來源提交並由既有 CI 產生發布檔；保留測試存檔與失敗證據。不要為回退 UI 清除玩家 localStorage。
