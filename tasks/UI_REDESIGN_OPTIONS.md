# UI 改版選項（RPG／大富翁風格）

狀態（2026-11-13）：**提案，待 code owner 決定方向**。非現行規格，不授權實作；`CURRENT_SPEC.md` 與 `BACKLOG.md` 未變更，方向決定後再登記 BACKLOG 項目並寫細部計畫。

- 前提（使用者 2026-11-13）：新風格**取代**現有介面，不與現有 4 主題並存切換。
- 本文對現有畫面的描述，依據 2026-11-12～13 作業中看過的程式碼（`docs/src/ui/*`、`docs/styles/*`、`docs/src/engine/game.js` 的繪製部分），未另做全面盤點；各項細部計畫時須重新盤點。
- 分級依 AGENTS §6.1（R0～R3），版本區分依 §9.2，皆為預估，細部計畫時重判。

## 0. 三種程度

| 程度 | 內容 | 遊戲規則／RNG | 預估分級 | 預估版本 |
|---|---|---|---|---|
| A | 只換外觀（CSS 模板） | 不變 | R2 | PATCH～MINOR |
| B | 新的呈現方式（同一份資料換畫面） | 不變 | R2（觸及事件順序者 R3） | MINOR |
| C | 改玩法 | 改變 | R3 | MAJOR（2.0.0） |

## 1. A：只換外觀

版面、DOM 順序、操作流程、顯示文字皆不變，只換 CSS 模板。

| # | 選項 | 內容 |
|---|---|---|
| A1 | 像素 RPG 風 | 點陣字體（須含日文字形）、深底白框的「視窗」面板、按鈕前加 ▶ 游標 |
| A2 | 冒險手帳風 | 羊皮紙紋理、墨水色、印章樣式的稱號與特性標籤 |
| A3 | 桌遊／大富翁風 | 紙鈔色系、棋盤格底紋、地契卡／機會卡外框、金額以鈔票樣式顯示 |
| A4 | 背景 | 現行球場背景（`stadium-background.css`）換成原野、城鎮或棋盤 |
| A5 | 圖示 | 以 CSS／SVG 在既有文字旁加圖示（劍、盾、金幣），DOM 不變 |
| A6 | 分享圖 PNG | 配色已可隨主題（UI-DESIGN-TOKENS-03）；字體跟隨新風格須 P4 |

- 前置：設計系統計畫 P3（UI-DESIGN-TOKENS-05，語意色＋推導）與 P4（UI-DESIGN-TOKENS-06，字體、字級、圓角、陰影、間距）。完成後新風格即一套模板。
- 限制：只靠 CSS，「看起來像 RPG」，操作仍是現行按鈕與表格。

## 2. B：新的呈現方式

遊戲規則與 RNG 不變，以新畫面呈現現有資料。

| # | 選項 | 內容 |
|---|---|---|
| B1 | RPG 狀態視窗 | 能力值改量條；年齡或年資對應 Lv、守位對應「職業」、特性對應「技能」 |
| B2 | 成長演出 | 能力上升時「レベルアップ！」與數字跳動 |
| B3 | 對話式事件 | 文字逐字顯示、NPC 頭像（監督、記者、家人）、選項以游標選單呈現，可鍵盤操作 |
| B4 | 大富翁式生涯棋盤 | 一格＝一個年度或階段（高校→大學→社會人→職業→引退），棋子標示目前位置，走過的格子顯示當年成績；生涯回顧為走完的棋盤 |
| B5 | 機會卡／命運卡 | 隨機事件以翻卡呈現；結果已由 RNG 決定，翻卡只是演出 |
| B6 | 世界地圖 | 移籍、聯盟（NPB、KBO、CPBL、MLB）以地圖呈現 |
| B7 | 資產表 | 年俸與收入以大富翁式資產表、鈔票呈現 |
| B8 | 結局 | 引退與殿堂改為 RPG 式片尾名單與稱號獲得畫面 |
| B9 | 音效／BGM | Web Audio，靜態配信可行；素材須原創或取得授權 |

- 限制：
  - 多數畫面在 `game.js` 內產生，而測試以原始碼文字掛鉤 `game.js`，改動須逐項確認耦合。
  - 演出不得呼叫 `R`，否則同 seed 結果改變（AGENTS §2）。
  - DOM 快照類 e2e（如 `game-view-dom-e2e`）須更新期待值，屬畫面規格變更，須核准。
- 每項建議各一個 PR，分開驗收。

## 3. C：改玩法

| # | 選項 | 內容 |
|---|---|---|
| C1 | 擲骰前進 | 每季或每年擲骰，停留格觸發練習、比賽或事件（大富翁核心） |
| C2 | 資產經營 | 買球場、贊助、投資、收租；改寫現行年俸與收入系統 |
| C3 | 回合制對決 | 打席／投球對決改為指令戰鬥（揮棒、觸擊、選球） |
| C4 | 探索地圖與商店 | 在城鎮與球場間移動，遇 NPC 觸發事件，購買球棒、手套等裝備加能力 |
| C5 | 經驗值與技能樹 | 取代現行能力分配 |
| C6 | 任務系統 | 主線（甲子園→選秀→殿堂）與支線 |
| C7 | 多人輪流 | 無伺服器，僅能同一裝置輪流 |

- 影響：
  - RNG 呼叫順序與次數全部改變，同 seed 產生不同人生。
  - 舊分享網址仍可開啟，但結果不同；AGENTS §3 禁止舊引擎切換與完全重現用的二重互換模式，舊人生無法重現。
  - 固定 seed 回歸、golden、殿堂平衡研究、`CURRENT_SPEC.md` 須重做。
- 實質上為新遊戲。

## 4. 「取代現有介面」的連帶影響

| 項目 | 內容 |
|---|---|
| 主題 | 現行 4 主題（standard、night、classic、scoreboard）是否移除；模板機制（P2～P4）仍可沿用，新風格本身為一套模板，可保留其明暗兩種變化 |
| 顯示文字 | 已核准的日文表示文、稱號（AGENTS §4）：A 原樣保留；B、C 若改措辭須逐項核准 |
| 測試基準 | 分享圖與 1.11.0 的像素比較（`replay-share-theme-e2e`）、DOM 快照、凍結檔的核准 overlay（`award-identity-policy.test`），期待值須重新核准 |
| 可讀性 | 點陣字體在長篇日文、320px 寬手機上的可讀性須實測 |
| 素材 | 頭像、地圖、像素圖須原創；可參考 RPG／桌遊類型，不得照搬特定遊戲的名稱、角色、美術或外觀 |
| 配信 | 維持靜態配信，不引入建置工具、npm 依賴或框架（AGENTS §5） |

## 5. 建議

- 取代介面且不破壞既有 seed：A＋部分 B（建議 B1、B3、B4、B2），可得大部分 RPG／大富翁感。順序：P2（UI-DESIGN-TOKENS-04）→ P3 → P4 → 新風格模板（A）→ B 逐項。
- C 相當於新遊戲，須先決定是否接受舊 seed 與舊分享連結全部失效，再談細節。
